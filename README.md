# Жэка Коммуналкин

## Команда Мобилизация

Чат-бот с мини-приложением в MAX, через который жители многоквартирных
домов общаются со своей управляющей компанией. Трек «Умный город».

Бот: https://max.ru/t260_hakaton_max_bot

- [Кирилл Лесовой](https://github.com/K1rL3s) - капитан, бэкенд
- [Даниил Карпенко](https://github.com/wannasleep66) - фронтенд
- [Даниил Неслуховский](https://github.com/nesclass) - аналитик
- [Артаган Мальсагов](https://github.com/ZeN220) - бэкенд

## Назначение

Когда в доме протечка, сломался лифт или не вывезли мусор, житель часто не
знает, кому и как об этом сообщить, а потом не видит, что стало с
обращением. С 1 сентября 2026 года УК обязаны работать с жителями через MAX
(ПП РФ от 26.01.2026 № 40), но готового инструмента для этого у большинства
УК нет. Жэка выполняет эту обязанность за УК.

Житель находит в Жэке свой дом, подает заявку с фото и видит ее статус и
срок, а бот сообщает ему о каждом изменении. Там же он передает показания
счетчиков, смотрит начисления и карточку дома, голосует в опросах.
Сотрудник УК принимает заявки, меняет статусы и назначает исполнителей,
видит показания и дашборд аналитики по своим домам, публикует объявления в
домовые чаты.

Бот один на все УК, поэтому у жителя один вход, какая бы УК ни управляла
его домом.

## Основной сценарий

1. Житель открывает бота и дает согласие на обработку персональных данных.
2. Находит свой дом: город - улица - дом, по геопозиции или по ссылке из
   домового чата.
3. Подает заявку: описание, категория, где проблема (в квартире или в доме),
   фото. Сразу получает номер и срок.
   В мини-приложении категорию подсказывает модель по описанию, в боте
   житель выбирает ее кнопкой.
4. Сотрудник УК получает от бота сообщение о новой заявке, принимает ее и
   меняет статус. Житель получает уведомление на каждом шаге, кнопка в
   уведомлении открывает заявку в мини-приложении.
5. Житель подтверждает квартиру и передает показания счетчиков: фото,
   распознанное значение, подтверждение, расход и сравнение со средним по
   дому.
6. Заявка выполнена - житель ставит оценку. Если сделано плохо, подает
   повторную заявку с фото и ссылкой на старую.

В боте короткие диалоги, уведомления и напоминания. Формы, списки, графики и
кабинет УК живут в мини-приложении, которое открывается кнопкой
«📱 Открыть приложение» под меню бота.

## Состав и архитектура

```
MAX ──HTTPS──> TLS на хосте ──> nginx :80 ─┬─ /          ─> web        статика мини-приложения
                                           ├─ /api/      ─> api        FastAPI + бот
                                           ├─ /files/    ─> api        загруженные фото
                                           ├─ /tiles/    ─> кэш nginx  подложки карты: OpenFreeMap, OSM
                                           └─ = /webhook ─> api        вебхук бота

api, worker ──> database (PostgreSQL 16)
            └─> redis (FSM бота, очередь и расписание taskiq)
```

| Сервис | Что делает |
|---|---|
| `web` | Мини-приложение: React + TypeScript, `@maxhub/max-ui`, MAX Bridge. Собирается в статику, которую отдает nginx внутри образа |
| `api` | FastAPI под gunicorn: REST для мини-приложения и бот на `maxo` в том же процессе, в режиме `polling` или `webhook` |
| `worker` | Фоновые задачи taskiq и их расписание в одном процессе: рассылка уведомлений, сообщения в домовые чаты, заполнение демо-данных, напоминания о показаниях, опросах, поверке и приеме, автозакрытие опросов и приемки, проверка вебхука бота каждые 10 минут, контроль сроков заявок, ежедневная очистка старых фото и файлов без ссылок |
| `migrations` | Прогоняет миграции alembic и завершается. Он же собирает образ бэкенда для `api` и `worker` |
| `database` | PostgreSQL 16 |
| `redis` | Redis 7 |
| `nginx` | Единственная точка входа, разводит запросы по путям |

Код:

- `backend/zheka/bot` - обработчики бота и диалоги;
- `backend/zheka/api` - REST для мини-приложения;
- `backend/zheka/core` - доменные модели и сервисы, общие для бота и API;
- `backend/zheka/infra` - база данных, клиент MAX, Yandex;
- `backend/zheka/broker` - фоновые задачи и расписание;
- `backend/zheka/seed` - демо-данные;
- `frontend/src` - мини-приложение.

Мини-приложение авторизуется подписанным `initData` из MAX. API проверяет
HMAC на токене бота и не принимает `initData` старше суток; чтобы проверять
API без MAX, есть тестовый токен (см. «Проверка API»). Данные разных УК
разделяет фильтр в репозиториях, так что на заявку чужой УК сотрудник
получает 404.

## Запуск

Нужны Docker с Compose v2 и токен бота MAX.

```sh
cp .env.example .env    # затем вписать MAX_TOKEN
docker compose up -d --build
```

Compose соберет образы, прогонит миграции и поднимет все сервисы. Первый
запуск занимает около минуты, если не считать скачивания базовых образов.
Готовность можно проверить так:

```sh
curl http://localhost/api/healthcheck
```

Пустую базу заполняют демо-данными этой командой:

```sh
docker compose run --rm api python -m zheka.seed
```

Локально API тоже пускает только с подписанной `initData` из MAX. Чтобы
проверять его запросами, впишите в `.env` любой `API_TEST_TOKEN`, например
`API_TEST_TOKEN=local`, и пересоздайте `api` командой
`docker compose up -d api`. После этого запросы из «Проверки API» работают
с адресом `http://localhost/api` и заголовком `Authorization: Bearer local`.

Бот локально работает в режиме `polling`, поэтому домен и сертификат не
нужны. Токен для этого берите отдельный, тестовый: пока на проде у бота
включен вебхук, long polling с тем же токеном обновлений не получит.

С заглушкой из `.env.example` вместо настоящего токена поднимается все,
кроме бота. API, документация `/api/docs`, статика мини-приложения,
миграции и заполнение базы работают. В логе `api` будет одна строка ERROR о
том, что MAX отверг токен и бот не запущен, а в логе `worker` та же ошибка
повторяется на каждое уведомление: без бота их некуда отправить. На проде в
режиме `webhook` такая ошибка валит запуск. Gunicorn пишет ERROR с причиной
и перезапускает воркер, а healthcheck не отвечает, пока бот не поднимется.

Мини-приложение открывается только из MAX: без подписанного `initData` или
тестового токена API отвечает 401. MAX открывает его по HTTPS-адресу из
настроек бота на платформе, и без публичного HTTPS-адреса локальную сборку
в MAX не увидеть. Мини-приложение удобнее проверять на развернутом боте.

## Окружение

Все переменные с комментариями лежат в `.env.example`. Compose читает
`.env` из корня репозитория.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `MAX_TOKEN` | да | Токен бота MAX |
| `MAX_BOT_MODE` | нет | `polling` (по умолчанию, локально) или `webhook` (прод) |
| `MAX_WEBHOOK_URL` | при `webhook` | Публичный HTTPS-адрес вебхука, `https://<домен>/webhook` |
| `MAX_SECRET_TOKEN` | при `webhook` | Секрет вебхука, сверяется с заголовком `X-Max-Bot-Api-Secret` |
| `DEEPLINK_ORG_REGISTER` | да | Скрытый код регистрации УК: 1-64 символа из латиницы, цифр, `_` и `-` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | да | Учетные данные PostgreSQL |
| `POSTGRES_HOST`, `POSTGRES_PORT` | вне Docker | Адрес PostgreSQL для запуска вне Docker, в compose зафиксирован |
| `REDIS_PASSWORD` | да | Пароль Redis |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB` | вне Docker | Адрес Redis для запуска вне Docker, в compose зафиксирован |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | нет | Yandex Vision OCR, Yandex AI Studio и SpeechKit. Без них продукт работает, но без подсказок |
| `YANDEX_MODEL` | нет | Текстовая модель AI Studio, по умолчанию `yandexgpt-5-lite` |
| `FILES_MAX_SIZE_MB` | нет | Предельный размер загружаемого фото, по умолчанию 10 |
| `FILES_DIR` | нет | Каталог фото для запуска вне Docker, в compose это `/data/files` |
| `API_CORS` | нет | Разрешенные источники через запятую, пусто - все. На проде `https://vkmax.k1rles.ru` |
| `API_TEST_TOKEN` | нет | Тестовый токен для проверки API без MAX, заголовок `Authorization: Bearer <токен>`. Пусто - выключено |
| `API_HOST`, `API_PORT` | нет | Адрес gunicorn для запуска вне Docker, в compose `0.0.0.0:7001` |
| `LOG_LEVEL`, `LOG_FORMAT` | нет | Уровень логов и формат: `PLAIN` локально, `JSON` на проде |
| `NGINX_PORT` | нет | Порт nginx на хосте, по умолчанию 80 |
| `BUILD_COMMIT` | нет | Коммит сборки в ответе `/api/healthcheck`, по умолчанию `dev`. Не в `.env`: `deploy.sh` передает `git rev-parse HEAD` в сборку образа |

## Порты

| Порт | Где | Кто |
|---|---|---|
| `80` (`NGINX_PORT`) | хост | nginx, единственный опубликованный порт |
| `7001` | сеть compose | `api` |
| `80` | сеть compose | `web` |
| `5432` | сеть compose | `database` |
| `6379` | сеть compose | `redis` |

HTTPS в репозитории не настроен, nginx слушает только 80. На проде TLS нужен
и мини-приложению, и вебхуку, причем строго на 443 и с настоящим
сертификатом: самоподписанный MAX отвергает.

## Внешние сервисы

| Сервис | Зачем | Без него |
|---|---|---|
| MAX Bot API | Бот, уведомления, мини-приложение | Не работает ничего |
| Yandex Vision OCR | Распознавание показания счетчика по фото | Житель вводит показание руками |
| Yandex AI Studio | Подсказка категории заявки и вероятности аварии по описанию | Житель выбирает категорию кнопками, опасные фразы ловят правила без модели |
| Yandex SpeechKit | Расшифровка голосового в боте, если MAX не прислал свою | Бот просит написать текстом |
| OpenFreeMap, OpenStreetMap | Подложки карты, через кэширующий прокси `/tiles/` на нашем домене | Карта не грузится, выбор дома и дома УК остаются списком |
| Nominatim (OpenStreetMap) | Адрес здания по тапу на карте, не чаще раза в секунду, с кэшем | Тап по дому не из справочника не показывает адрес |

Подсказку категории и OCR мини-приложение запрашивает с таймаутом 3
секунды, в боте OCR и SpeechKit работают в фоновой задаче. Если Yandex AI
Studio отвергла ключ, подсказка категории выключается до перезапуска процесса.
Модель только предлагает категорию: житель видит ее и может выбрать другую.
Тревогу модель может только поднять, когда правила молчат, но не снять.

Из ГИС ЖКХ сервис берет только паспорт дома, и то заранее, при сборе
демо-данных: API в ГИС ЖКХ не ходит. Оплаты нет: платеж в мини-приложении
демонстрационный, деньги не списываются.

### Карта

Карта сделана на MapLibre GL. Подложек шесть: пять векторных от OpenFreeMap
и классическая OpenStreetMap.

Все файлы карты (стили, тайлы, шрифты, спрайты) идут через наш nginx по
пути `/tiles/...`. Браузер жителя обращается только к нашему домену, и
провайдерам nginx не передает ни IP, ни cookie, ни другие заголовки жителя.
Тайлы, которые уже запрашивали, nginx отдает из своего кэша и не нагружает
открытые серверы повторно. Кэш занимает до 2 ГБ в томе
`<проект>_zheka-tiles` и переживает пересоздание контейнера.

Яндекс Карты и 2ГИС не подошли: их бесплатные условия не допускают
приложений за авторизацией, а мини-приложение MAX именно такое. Публичного
SDK веб-карты у VK нет.

Если российские провайдеры начнут замедлять Cloudflare для нашего сервера,
запасной вариант - собственные векторные тайлы трех городов в PMTiles.

Атрибуция подложки, которой требуют лицензии, видна при открытии карты, а
после первого сдвига сворачивается в кнопку «i».

## Данные

Мы храним пользователей MAX и их согласие на обработку персональных данных
(версию и дату), дома, квартиры и лицевые счета, заявки с фото, показания
счетчиков, начисления, опросы, объявления и события для аналитики.

- Согласие запрашивается до выбора дома, со ссылкой на политику обработки
  данных. Без согласия бот и мини-приложение дальше не пускают.
- Персональные данные жителя видит только УК его дома.
- Фото и документы PDF лежат на диске в `backend/content` под UUID-именами.
  Ссылку на файл API подписывает на час и выдает только тем, кому файл
  положено видеть.
- Данные PostgreSQL и Redis живут в томах `<проект>_zheka-postgres` и
  `<проект>_zheka-redis`, где проект - имя папки репозитория.

### Откуда демо-данные

- **Реальные открытые данные:** дома и управляющие организации - Реформа
  ЖКХ (reformagkh.ru), кадастровый номер, износ, состояние и класс
  энергоэффективности в паспорте дома - публичная часть ГИС ЖКХ
  (dom.gosuslugi.ru), координаты - © участники OpenStreetMap, лицензия
  ODbL 1.0. Под паспортом дома указаны источник и дата.
- **Модельные, сгенерированные для демонстрации:** все остальное -
  организации «Демо-УК ...», их жители, начисления, показания, заявки и
  документы. В мини-приложении модельные разделы помечены на экране.
- Подробнее - в `backend/README.md`.

## Тестовые данные

`python -m zheka.seed` заполняет пустую базу одной транзакцией. На
развернутом боте то же делает команда `/seed` в личке с ботом.

Демо-история охватывает полгода и заканчивается днем заполнения, а дашборд
по умолчанию и сравнение с другими УК считают последние 30 дней, так что
базу лучше заполнять ближе к проверке.
Заполнить повторно можно только пересозданную базу: `docker compose down -v`,
затем запуск и заполнение.

### Демо-доступ

В MAX у каждого свой настоящий аккаунт, поэтому выдать «логин жителя»
нельзя. Роль выдает ссылка в бота с параметром `start`:

```
https://max.ru/t260_hakaton_max_bot?start=demo_resident_1
```

| Параметр | Что выдает |
|---|---|
| `demo_resident_N` | Собственную подтвержденную квартиру в первом доме организации N, с начислениями и показаниями за полгода и арендатором, которому можно завершить аренду |
| `demo_staff_N` | Роль сотрудника организации N |
| `demo_admin_N` | Роль администратора организации N |
| `demo_executor_N` | Роль исполнителя организации N вместо роли сотрудника или администратора в ней. На вас назначается последняя новая или принятая заявка вашей демо-квартиры, и бот присылает ее карточку. Роль сотрудника возвращает ссылка `demo_staff_N` |

N от 1 до 5. У каждого проверяющего-жителя своя квартира, так что жители не
видят действий друг друга. Сотрудники одной демо-УК видят общие входящие
заявки, поэтому для независимой проверки берите разные N. Один аккаунт
может пройти по нескольким ссылкам и получить несколько ролей сразу. Если
база не заполнена, ссылка ответит «Демо-доступ еще не готов».

Демо-УК общие, поэтому их сотрудники видят имена других проверяющих. Помешать
друг другу проверяющие не могут: заблокировать жителя или снять с него
подтверждение квартиры можно только у модельного жителя, снять или сменить
председателя дома - только модельного или себя, отозвать - только свое
приглашение, завершить досрочно - только свои плановые работы. Объявление
в личку из демо-УК приходит только его автору.

Настройки, исполнители по категориям и часы приема демо-УК открыты только
для чтения, исключить из нее сотрудника тоже нельзя.

Заявка становится коллективной, когда об одной проблеме в доме за сутки
сообщают 3 квартиры. Администратор меняет порог в настройках организации.
В демо-УК порог поднят до 10, иначе заявки проверяющих из одного демо-дома
склеивались бы между собой. Чтобы увидеть коллективную заявку с одного
аккаунта, нажмите на своей открытой заявке «Демо: соседи сообщили». До
четырех модельных жителей дома из других квартир подадут заявку той же
категории, и она станет коллективной. Сотрудникам о заявках соседей бот не
пишет. У заявок о счете квартиры этой кнопки нет: они не склеиваются.

Лицевой счет у всех квартир - номер квартиры, дополненный нулями до 10
цифр: у кв. 12 это `0000000012`. С ним в мини-приложении можно подтвердить
любую квартиру, не только демо-квартиру из ссылки. Исключение - квартиры
проверяющих `Д...`: они подтверждены сразу, а счет у них случайный, чтобы
чужую демо-квартиру не занял другой проверяющий.

## Сценарий проверки

1. Откройте `https://max.ru/t260_hakaton_max_bot?start=demo_resident_1`.
   Бот попросит согласие на обработку данных, дайте его.
2. Бот ответит «🎟 Демо-доступ открыт: ваша квартира ...». Откройте
   приложение кнопкой «📱 Открыть приложение».
3. Во вкладке «Заявки» подайте заявку о протечке: опишите проблему, модель
   подскажет категорию, укажите, где проблема, приложите фото. Заявка
   появится с номером, статусом
   и сроком. Чтобы не ждать срок, нажмите под ним «⏩ Демо: срок истек»
   (кнопка есть только в демо-УК): бот пришлет «🔴 Срок по заявке ... истек»
   с кнопкой «📄 Жалоба в ГЖИ», а в карточке заявки появится блок жалобы:
   кнопка «Получить PDF в чат с ботом» через несколько секунд пришлет в
   диалог файл `zhaloba-N.pdf` с пометкой «ДЕМО», ниже телефон и сайт ГЖИ
   региона и текст для копирования. Сотрудникам демо-УК придет «🔴 Заявка ... просрочена». Там же
   нажмите «Попросить руководство УК»: бот подтвердит «⬆️ Руководство УК
   уведомлено ...», сотрудники демо-УК получат «⬆️ Житель просит руководство
   вмешаться», а в кабинете УК заявка встанет первой во входящих. Последний
   шаг блока, «3. Куда ещё», раскрывается по нажатию: адресаты по категории
   заявки с темами ГИС ЖКХ. У протечки это ГЖИ и прокуратура, у мусора
   первым идет регоператор ТКО, у спора по начислению добавляется тарифный
   орган региона.
4. В Профиле откройте карточку дома: УК, раздел «Куда звонить» с
   телефонами городских служб и ГЖИ региона, что УК обязана делать по ПП РФ
   № 290 (кнопка «Показать перечень работ»), тарифы, капремонт, документы.
5. На Главной нажмите «Передать» и передайте показания счетчика. Его можно
   сфотографировать или приложить любое фото счетчика, значение
   распознается само или вводится вручную. Приложение покажет расход и
   сравнение со средним по дому. Фото обязательно, потому что по нему УК
   разбирает споры о показаниях.
6. Тем же аккаунтом откройте
   `https://max.ru/t260_hakaton_max_bot?start=demo_staff_1`. Бот ответит
   «🎟 Демо-доступ открыт: вы сотрудник ...» и даст кнопку
   «🧑‍💼 Открыть кабинет УК». Автору заявки сообщение сотрудникам о ней не
   приходит. Чтобы его увидеть, откройте эту ссылку вторым аккаунтом до
   шага 3.
7. В кабинете УК во вкладке «Заявки» нажмите фильтр «Статус: Все»,
   выберите «Новые» и откройте свою заявку, ее номер виден в строке списка.
   Фильтр «Место» оставит «Личные» заявки из квартир или «Общие» - о
   подъезде, дворе и общем имуществе.

   В «Переписке с жителем» включите «Нужен ответ жителя» и спросите,
   например, «Под вами 45 или 47 квартира?». У заявки появится плашка «Ждёт
   ответа жителя», а вам как автору бот пришлет карточку «❓ УК уточняет по
   заявке ...». Нажмите в ней «✍️ Ответить» и напишите «47». Бот ответит
   «✅ Ответ передан в УК», а в кабинете плашка сменится на «Житель
   ответил». Ответить можно и в приложении, в панели «УК ждёт вашего
   ответа» на экране заявки.

   Затем примите заявку в работу, начните работы и отправьте на приемку.
   Закрывает заявку житель, когда принимает работу, а если он этого не
   сделает, заявка закроется сама через 48 часов. Пока работу не сдали на
   приемку, житель может отменить заявку сам, с причиной: кнопкой
   «↩️ Отменить заявку» под «✅ Заявка №... отправлена в УК» в боте или
   «Отменить заявку» внизу экрана заявки. У заявки появится плашка
   «Отменена жителем».
8. На каждую смену статуса бот присылает жителю уведомление с кнопкой
   «📱 Открыть заявку». Когда заявка уходит на приемку, приходит карточка с
   фото: работу можно принять и оценить прямо в чате или в приложении. Если
   нажать «👎 Сделано плохо», написать, что не так, прислать фото и нажать
   «📨 Отправить», уйдет повторная заявка со ссылкой на старую. Без фото
   вернуть работу нельзя, кроме ошибки в показаниях и спора по начислению.
9. Во вкладке «Аналитика» кабинета УК - дашборд по домам организации.
10. Подайте еще одну заявку, как в шаге 3, и откройте
    `https://max.ru/t260_hakaton_max_bot?start=demo_executor_1`. Бот ответит
    «🎟 Демо-доступ открыт: вы исполнитель ...» и пришлет карточку заявки.
    Нажмите «🚗 Выехал», затем «🏁 Готово» и пришлите фото результата, и
    этот же аккаунт получит карточку приемки. Ссылка заменяет роль
    сотрудника в этой УК, вернуть ее можно ссылкой `demo_staff_1`.

Напоминания бот шлет по расписанию: о приеме показаний, поверке счетчиков,
опросах и записи на прием. Чтобы не ждать, отправьте боту `/demo`, и он
сразу пришлет по одному настоящему напоминанию каждого вида, с кнопками.
Серийный номер счетчика и адрес бот берет из вашей демо-квартиры, а если ее
нет, подставляет модельные. В меню команд `/demo`, как и `/seed`, не показана.

## Ожидаемое поведение

- `/start` без параметров открывает главное меню «👋 Жэка Коммуналкин на
  связи». Пока дом не выбран, в нем кнопки «🔎 Найти дом», «📝 Подать
  заявку» и «📱 Открыть приложение». Когда дом выбран, меню показывает
  адрес, а поиск превращается в кнопку «🔎 Другой дом». Сотруднику УК меню
  напоминает, что кабинет УК в приложении, и дает кнопку
  «🧑‍💼 Открыть кабинет УК».
- Без согласия на обработку данных бот показывает только экран согласия.
- `/help` выводит список команд.
- Когда сотрудник меняет статус заявки, бот пишет жителю.
- Когда до конца срока открытой заявки остается четверть (от 1 до 24
  часов), сотрудникам УК и исполнителю приходит «⏳ ... осталось N ч».
  После срока им же приходит «🔴 ... просрочена», жителю - сообщение с
  кнопкой «📄 Жалоба в ГЖИ», председателю дома - сообщение без данных
  автора. Каждое сообщение уходит один раз, заявки на приемке не трогаются.
- Если житель просит руководство вмешаться в просроченную заявку,
  сотрудники УК и исполнитель получают «⬆️ Житель просит руководство
  вмешаться», а житель - подтверждение «⬆️ Руководство УК уведомлено ...».
  Попросить можно один раз на заявку.
- Если УК задает вопрос с включенным «Нужен ответ жителя», автор получает в
  боте карточку с кнопками «✍️ Ответить» и «📱 Открыть заявку». Когда
  житель отвечает из бота или приложения, сотрудники УК и исполнитель
  получают «💬 Житель ответил по заявке ...». Статус и срок заявки вопрос не
  меняет.
- Если житель отменяет заявку, сотрудники УК и исполнитель получают
  «↩️ Житель отменил заявку ...» с причиной, а причина остается в переписке
  заявки. Заявку на приемке или закрытую отменить нельзя.
- Смена статуса коллективной заявки двигает только отставшие заявки группы,
  ушедшую вперед она не трогает.
- Короткое сообщение с опасной фразой («Пахнет газом») открывает в боте
  экран аварии вместо меню. Уведомление сотрудникам о заявке с опасной
  фразой начинается строкой «🚨 Опасность: ...».
- Когда собственник завершает аренду, арендатор получает «🚪 Собственник
  завершил аренду ...», и доступ к квартире у него закрывается.
- На сообщение, которое бот не разобрал (короткий текст, незнакомая
  команда), он отвечает «🤔 Не понял сообщение, вот что я умею» и
  показывает меню.
- На нажатие кнопки в старом сообщении бот отвечает «🔄 Это окно устарело,
  открываю меню заново» и открывает меню.
- На недопустимое действие, например с чужой заявкой, бот коротко
  объясняет причину, и диалог продолжается без перезапуска.
- Если показание меньше предыдущего, бот предупреждает: «Новое значение
  меньше предыдущего, уточните показание». Показание не за текущий период
  или за период, по которому уже выставлена квитанция, он отклоняет с
  причиной.
- Без ключей Yandex распознавание возвращает пустое значение, а подсказка
  категории - `null`. Житель заполняет эти поля сам, и сценарий не
  прерывается. Опасные фразы и без ключей ловят правила.
- `GET /api/healthcheck` - 200, документация API - `/api/docs`.
- Новая заявка жителя - сообщение сотрудникам УК с кнопкой, открывающей
  заявку в кабинете. Автору заявки оно не приходит, даже если он сотрудник.
- Неожиданная ошибка в боте - «⚠️ Что-то пошло не так, попробуйте еще раз»,
  и меню открывается заново.
- Запрос к API без `initData` и без тестового токена - 401 с причиной.

## Проверка API

API мини-приложения - собственный API решения: `https://vkmax.k1rles.ru/api`.
Контракт описан в `openapi.yaml` (OpenAPI 3.1), обязательные проверки - в
`DATA-API.yaml` по схеме организаторов DATA-API 1.0. Схему и совпадение
путей с `openapi.yaml` проверяет `backend/tests/test_data_api.py`.

Мини-приложение авторизуется `initData` из MAX, а ее нельзя получить вне
MAX, и живет она сутки. Поэтому для проверки есть тестовый токен
`34c63235dea4b1fb95ce89a9f108fc18` в заголовке
`Authorization: Bearer <токен>`, он же на служебном слайде презентации. В
самом `DATA-API.yaml` токена нет.

Токен открывает одну учетную запись, «Проверяющий API». С ним идут
проверки с ролями `resident` и `staff`, а проверки с ролью `public` идут
без токена. Первые две проверки в `DATA-API.yaml` дают этой записи согласие
и демо-доступ, после чего у нее есть квартира в демо-УК №5 и роль
сотрудника этой УК. Обе проверки можно повторять.

Проверки API и жюри друг другу не мешают. Ссылки со служебного слайда ведут
в демо-УК №1, а демо-УК №5 закрыта для всех, кроме токена. Сам токен не
пускают в другие демо-УК и к роли администратора (`/demo/activate` с ними
отвечает 403), и коды сотрудников он не активирует.

Свои заявки токен ведет только до статуса «Принята»: на тестовой заявке из
проверок `DATA-API.yaml` держится проверка `staff_status`, которая
переводит ее в этот статус. Засеянные заявки демо-УК №5 он ведет по всем
статусам. Проверки заявок передают `X-House-Id`, потому что токен может
привязаться и к другим домам, а житель нескольких домов без этого
заголовка получает 403.

```sh
TOKEN=34c63235dea4b1fb95ce89a9f108fc18
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"version":"1.2"}' https://vkmax.k1rles.ru/api/me/consent
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":5}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" https://vkmax.k1rles.ru/api/me
```

Вход по токену включает переменная `API_TEST_TOKEN`, пустая выключает. На
проде действует значение выше, локально - то, что вписано в `.env`.

## Памятка проверяющему

Стенд отвечает, из какого коммита собран:

```sh
curl https://vkmax.k1rles.ru/api/healthcheck
# {"ok":true,"commit":"<хэш>"}
```

`commit` совпадает с хэшем на служебном слайде презентации. Коммит
запечен в образ при деплое и после пересоздания базы не меняется, локальная
сборка отвечает `dev`. С 30.09 по 29.10 `.github/workflows/uptime.yml`
раз в 15 минут, а после 14.10 раз в час проверяет healthcheck и коммит,
главную страницу и отказ вебхука без секрета. При сбое бот пишет капитану
команды в MAX.

Отказы API приходят в одном конверте
`{"status", "ok": false, "trace_id", "error": {"title", "detail"}}`,
причина - в `error.detail`. Строки покрыты тестами или проверками в
`DATA-API.yaml`, кроме вебхука: запрос без секрета отвергает maxo, а без
`MAX_SECRET_TOKEN` бот в режиме `webhook` не запускается.

| Действие | Код | Текст |
|---|---|---|
| `GET /api/me` без `initData` и токена | 401 | «Нужна initData в заголовке WebAppData или тестовый токен» |
| Чужая заявка, `GET /api/requests/1` с токеном | 404 | «Заявка не найдена» |
| Токен и `POST /api/demo/activate` с `{"number":1}` | 403 | «Тестовый токен получает только роль сотрудника демо-УК №5» |
| Исполнитель обращается к API кабинета УК | 403 | «Исполнитель работает только через бота» |
| Статус заявки назад, `POST /api/admin/requests/{id}/status` | 409 | «Статус заявки назад не двигается» |
| Не изображение и не видео по содержимому, даже с `type=image/jpeg`, в `POST /api/files` | 400 | «Поддерживаются только изображения и видео MP4 или MOV» |
| Фото больше 10 МБ в `POST /api/files` | 400 | «Файл больше 10 МБ» |
| 31-я загрузка за час, счетчик у каждого процесса `api` свой | 429 | «Слишком много запросов, попробуйте позже» |
| Тело не по схеме, `{"number":9}` в `POST /api/demo/activate` | 400, не 422 | «Поле: ('body', 'number')» и тип ошибки `less_than_equal` |
| Администратор демо-УК меняет ее настройки, `PUT /api/admin/org/settings` | 403 | «Демо-УК общая для всех проверяющих, это действие в ней отключено» |
| `POST /webhook` без заголовка `X-Max-Bot-Api-Secret` | 403 | `{"detail":"Forbidden"}` от maxo, без конверта |

Строки с токеном - после команд из «Проверки API»:

```sh
TOKEN=34c63235dea4b1fb95ce89a9f108fc18
curl https://vkmax.k1rles.ru/api/me
curl -H "Authorization: Bearer $TOKEN" https://vkmax.k1rles.ru/api/requests/1
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":1}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":9}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" -F "file=@README.md;type=image/jpeg" \
  https://vkmax.k1rles.ru/api/files
curl -X POST -d '{}' https://vkmax.k1rles.ru/webhook
```

## Возможности MAX сверх минимума

Главное здесь - домовые чаты: УК пишет жителям там, где они уже общаются.
Бот привязывается к чату дома, публикует туда объявления из кабинета УК и
ведет список закрепов.

Это можно проверить одним аккаунтом. Получите роль сотрудника по ссылке
`demo_staff_1`, создайте в MAX группу и добавьте в нее бота. Бот напишет в
личку, спросит, к какому дому привязать чат, и попросит права
администратора. Потом он поздоровается в чате с кнопкой
«🏠 Присоединиться к дому». Объявление из вкладки «Объявления» кабинета УК
придет в этот чат, а `/pin` в ответ на сообщение добавит его в список
закрепов.

Что еще есть:

- Бот и мини-приложение связаны. Уведомление о заявке и карточка приемки
  открывают заявку в приложении, сотруднику - в кабинете УК, а в меню бота
  у сотрудника есть кнопка «🧑‍💼 Открыть кабинет УК». Кнопка политики в
  согласии открывает политику. Ссылки `?start=` из QR, приглашений и
  демо-доступа сразу выбирают дом, организацию или роль.
- Приемку работы с фото, оценку и повторную заявку житель делает прямо в
  чате с ботом. Исполнитель ведет заявку кнопками «🚗 Выехал» и «🏁 Готово»
  без мини-приложения и присылает фото результата, и тогда в карточке
  приемки видно «было - стало». Бот обновляет карточку на месте и не шлет
  новую на каждое действие. Карточку исполнителя одним аккаунтом можно
  открыть по ссылке `demo_executor_1`, см. шаг 10 сценария проверки.
- QR на подъезд выдает администратор: получите роль по ссылке
  `demo_admin_1` и в кабинете УК откройте «Дома» - дом - QR. Ссылка из QR
  открывает бота с уже выбранным домом и подъездом.
- **QR с квитанции.** Собственник подтверждает квартиру платежным QR с
  квитанции ЖКУ вместо ручного ввода: кнопка «Сканировать QR квитанции»
  открывает сканер MAX, можно навести камеру или выбрать снимок из галереи.
  Сервер берет из QR только лицевой счет (`persAcc`) и саму строку не
  хранит. Демо-квитанция [`docs/demo-receipt-qr.png`](docs/demo-receipt-qr.png)
  подходит к кв. 12 любого дома демо-УК.
- **Три уровня уведомлений** по категориям в профиле: со звуком, без звука,
  выключены. Статусы своих заявок выключить нельзя.

Карточку исполнителя одним аккаунтом открывает ссылка `demo_executor_1`,
см. шаг 10 сценария проверки.

## Обращения и ПП РФ № 416

Работу с заявками мы сверили с Правилами управления МКД (ПП РФ от
15.05.2013 № 416) в редакции от 20.06.2026:

- п. 35: обращение можно направить через MAX, и официальный ответ идет тем
  же каналом. Житель подает заявку в боте или мини-приложении, а смену
  статуса и ответ УК получает сообщением бота. Обращение по телефону
  сотрудник УК заводит заявкой сам, на прием житель записывается в
  мини-приложении.
- п. 36: на вопросы вне пунктов 31, 32 и 34 УК отвечает не позднее 10
  рабочих дней. Этот срок у споров по начислению и у «Другого».
- п. 34: сведения по общедомовым приборам учета и копии актов УК выдает не
  позднее 3 рабочих дней. Часть раскрываемой информации (УК и ее контакты,
  тарифы, капремонт, документы) житель видит в карточке дома без запроса.
- п. 38: запрос и ответ хранятся 3 года. Заявки и переписка по ним не
  удаляются.
- Номер заявки и срок житель получает сразу при подаче, как п. 17.2
  требует от аварийно-диспетчерской службы.

Срок записывается в заявку при подаче. Бот, карточка и текст для ГЖИ
показывают под ним основание:

| Категория | Принять | Выполнить | Основание |
|---|---|---|---|
| Протечка | 30 минут | 3 суток | ПП РФ № 416, п. 13 |
| Водоснабжение | - | 4 часа | ПП РФ № 354, прил. 1, п. 1, 4 |
| Отопление | - | 16 часов | ПП РФ № 354, прил. 1, п. 14 |
| Электричество | - | 24 часа | ПП РФ № 354, прил. 1, п. 9 |
| Лифт, мусор | - | 24 часа | срок сервиса, норматива нет |
| Подъезд, двор | - | 3 суток | срок сервиса, норматива нет |
| Ошибка в показаниях | - | 10 рабочих дней | ПП РФ № 354, п. 31 «е(2)» |
| Спор по начислению | - | 10 рабочих дней | ПП РФ № 416, п. 36 |
| Другое | - | 10 рабочих дней | ПП РФ № 416, п. 36 |

У спора по начислению 10 рабочих дней - это срок ответа. Саму проверку
начисления ПП РФ № 354, п. 31 «д» требует провести при обращении, а если
это невозможно, то в срок по договоренности, но не дольше 1 месяца.
Подсказка под сроком об этом пишет. Тексты пунктов с редакцией и
источником: [ПП РФ № 354, п. 31](docs/norms/pp354-p31.md),
[ПП РФ № 416, пп. 34-37](docs/norms/pp416-p34-37.md).

Рабочие дни считаются «со дня получения»: отсчет начинается со дня после
подачи по времени дома, а срок истекает в конце 10-го рабочего дня.
Календарь выходных и праздников на 2026 год взят из ТК РФ, ст. 112 и
постановления Правительства от 24.09.2025 № 1466, на 2027 год - из
постановления от 17.09.2026 № 1187 (`backend/zheka/core/workdays.py`). С
2028 года выходными считаются только субботы, воскресенья и праздники из
ст. 112, без переносов.

Минимальный перечень работ по содержанию общего имущества (ПП РФ от
03.04.2013 № 290 в ред. от 07.03.2025) лежит в
`backend/zheka/core/pp290.json`: 144 работы в 32 пунктах. Разбор текста взят
у команды KokInside, мы убрали из него три обрывка заголовков и сверили
остальное с текстом КонсультантПлюс. Карточка дома показывает перечень в
разделе «Что УК обязана делать», а заявка под сроком ссылается на пункты
своей категории, и текст для ГЖИ их повторяет:

| Категория | Пункты ПП РФ № 290 |
|---|---|
| Протечка, водоснабжение | п. 18, 28 |
| Отопление | п. 17, 19, 28 |
| Электричество | п. 20, 28 |
| Лифт | п. 22, 28 |
| Подъезд | п. 13, 23, 28 |
| Мусор | п. 14, 26(1), 28 |
| Двор и территория | п. 24, 25, 28 |
| Другое | п. 28 |

П. 28 - устранение аварий в предельные сроки и выполнение заявок населения.
У ошибки в показаниях и спора по начислению ссылок нет: перечень только про
содержание общего имущества.

В блоке «Отвечает» у всех категорий стоит УК дома, у водоснабжения тоже.
Стояки и отводы до первого отключающего устройства входят в общее
имущество (ПП РФ № 491, п. 5), граница с сетями водоканала проходит по
внешней стене дома (там же, п. 8), о перебоях житель сообщает в
аварийно-диспетчерскую службу (ПП РФ № 354, п. 34, пп. 105-106). Аварию на
городской сети УК передает водоканалу сама, а житель видит на заявке
телефон водоканала города: «Если без воды и соседние дома, звоните в ...».

У просроченной заявки шаг «3. Куда ещё» называет адресатов кроме
руководства УК (`frontend/src/features/request/domain/recipients.ts`). ГЖИ
есть у каждой категории: государственный жилищный надзор проверяет
содержание общего имущества, коммунальные услуги и плату (ЖК РФ, ст. 20,
ч. 1, 3). Муниципальный жилищный контроль с 01.09.2026 отменен (ЖК РФ,
ст. 14, ч. 1, п. 9 утратил силу по закону от 20.02.2026 № 23-ФЗ), поэтому
администрация города появляется только у двора за границей участка дома.
Регоператор ТКО добавляется к мусору, тарифный орган региона - к спору по
начислению, водоканал, теплосеть и сетевая организация - к перебоям, когда
без ресурса и соседние дома. Последняя строка у всех - прокуратура:
госорган отвечает на обращение за 30 дней и может продлить срок еще на 30
с уведомлением (59-ФЗ, ст. 12). Рядом с адресатом стоят коды и названия
тем справочника НСИ 220 ГИС ЖКХ
(`https://dom.gosuslugi.ru/opendataapi/nsi-220/v1`), у ГЖИ всегда есть
тема 3.13 «Игнорирование обращений в управляющие компании». Коды и
названия сверены с выгрузкой справочника 29.09.2026.

## Известные ограничения

- У лифта, мусора, подъезда и двора срок сервиса. Норму под ним мы не
  сверяли, поэтому строки с основанием под сроком у них нет ни в карточке,
  ни в боте.
- Срок реакции есть только у протечки: флага «авария» у заявки нет.
- На вопрос о раскрываемой информации п. 34 требует ответить не позднее
  следующего дня, а копии актов выдать за 3 рабочих дня. У категории
  «Другое» срок 10 рабочих дней.
- Производственный календарь в коде статичный. На 2028 год его нужно
  дополнить по новому постановлению о переносе выходных, иначе переносы и
  праздники, выпавшие на выходные, не учитываются.
- HTTPS в репозитории не настроен: на проде TLS завершает nginx на хосте,
  перед compose.
- Паспорт дома из ГИС ЖКХ обновляется только новым прогоном
  `scripts/fetch_seed_data.py` и пересевом. Дом, добавленный жителем, паспорта
  не получает. Число подъездов ГИС ЖКХ не отдает, поэтому у домов, чью
  карточку на reformagkh.ru не удалось прочитать, оно оценено и помечено
  «оценка».
- Письмо в неподключенную УК житель отправляет сам, из своей почты: сервис
  только собирает текст и открывает почтовое приложение, ничего не хранит и
  не отправляет. Почта УК взята из реестра Реформы ЖКХ и могла устареть; у
  6 из 77 реестровых УК ее нет, тогда остается скопировать текст. Откроет ли
  MAX почтовое приложение по ссылке `mailto:`, зависит от клиента.
- Обмена с ГИС ЖКХ нет, начисления и оплата модельные. Для настоящих
  данных нужны выгрузка начислений из биллинга УК в таблицу `charges` и
  платежный шлюз УК (эквайринг или СБП). Чтобы передавать показания в ГИС
  ЖКХ, нужен SOAP-обмен, а для него - электронная подпись УК и регистрация
  информационной системы в личном кабинете УК.
- Регистрацию УК подтверждает только скрытый код. В настоящем продукте
  здесь нужна ЕСИА или письмо на официальный домен организации из реестра.
- Привязка к дому не требует подтверждения квартиры. Так задумано для MVP:
  житель сразу видит опросы и объявления дома, голосует без веса площади и
  подает заявки. Начисления, счетчики, список жильцов квартиры и голос с
  весом площади открываются только после подтверждения.
- Объявление подъездам получают только жители, которые выбрали квартиру из
  справочника дома: у квартиры, введенной вручную, нет подъезда. Объявление
  квартирам получают только их подтвержденные жители, а выбрать квартиры может
  только администратор УК, потому что список жителей сотруднику закрыт.
- Запись на прием к УК тоже доступна сразу после привязки и не ограничена
  числом записей на человека. В настоящем продукте запись стоит открывать
  только подтвержденным жителям и ограничить одной-двумя активными записями.
- Юридически значимое общее собрание собственников не проводится: опросы
  только помогают заранее собрать мнения.
- Сканер QR (`openCodeReader`) на живых телефонах мы не проверяли. Кнопка
  сканирования есть только в MAX на iOS и Android, в MAX Web и на десктопе
  лицевой счет вводят руками. На многих квитанциях получатель - расчетный
  центр, и лицевой счет из QR совпадет с номером в системе, только если УК
  заводит те же номера.
- Бот не может написать жителю первым, если тот ни разу его не открывал.
- Домовые чаты бот сам не создает, его добавляет в чат председатель или
  УК. По словам эксперта трека, список чатов бота в MAX хранит только
  последнюю тысячу чатов, поэтому привязанные домовые чаты бот берет из
  своей базы, а не из этого списка.
- MAX ограничивает бота 30 запросами в секунду, так что рассылка тысяче
  жителей занимает около 35 секунд.
- Демо-история заканчивается днем заполнения базы, и через 30 дней
  сравнение с другими УК и дашборд за 30 дней пустеют.
- Жалоба в ГЖИ в PDF - черновик: ФИО и адрес для ответа житель вписывает
  сам, соседи подписываются на распечатке, сервис эти данные не собирает.
  Файл приходит только в чат с ботом: скачивание прямо в мини-приложении
  (`downloadFile` в MAX Bridge) не сделано.
- Адресаты шага «3. Куда ещё» без телефонов: телефон и сайт ГЖИ региона
  стоят в шаге 2, остальные службы города - в карточке дома. Совпадают ли
  коды тем НСИ 220 с формой в Госуслугах «Дом», мы не проверяли, поэтому
  рядом с кодом стоит название темы. Роспотребнадзор по качеству воды в
  список не входит.
- «Куда звонить» есть только в Москве, Санкт-Петербурге и Казани, в другом
  городе этих регионов карточка покажет только ГЖИ. В Москве нет газа и
  вывоза мусора: номер, который не удалось подтвердить на официальном сайте,
  в справочник не попал. Номера сверены вручную 29.09.2026 и могут
  устареть. Теплоснабжающих и сбытовых организаций в городе бывает
  несколько: справочник называет одну, свою житель смотрит в квитанции.
- Кабинет УК не выгружает заявку документом. В домовых чатах кнопка
  мини-приложения есть только под напоминанием об опросе и под объявлением
  с документами.
- Плановые работы: время начала и окончания УК вводит по часовому поясу
  первого выбранного дома. Предупреждение в форме заявки появляется, только
  если у работ указана категория. «Работы завершены» приходит только после
  «Завершить досрочно», окончание по сроку жителям не сообщается. Документ
  PDF открывается ссылкой, в мобильном клиенте MAX это не проверено.
- Лимиты на пользователя в час: 60 вызовов Yandex на подсказку категории,
  распознавание фото и расшифровку голосовых вместе, 30 загрузок фото
  и документов,
  5 новых домов на карте и 60 запросов адреса по точке. Счетчики живут в
  памяти процесса: перезапуск их обнуляет, а каждый воркер gunicorn в `api`
  и процесс `worker` считают отдельно.
- Ответ на вопрос УК бот принимает только после кнопки «✍️ Ответить» в
  карточке вопроса: текст без нее в УК не попадет, а длинный бот предложит
  оформить новой заявкой. Срок заявки на время вопроса не останавливается,
  исполнитель переписку в боте не видит.
- Файл, который за сутки ни к чему не прикрепили, удаляет ежедневная
  очистка, как и фото закрытых заявок и показаний старше 12 месяцев.
- «Проблемы дома» собирают заявки без коллективной в одну строку по
  категории: подъезда у заявки нет, поэтому две разные протечки в доме -
  одна строка «2 квартиры сообщили». В демо-УК первый дом общий у всех
  проверяющих, и на доске видны категории их заявок.
- Крупный текст (Профиль - «Размер текста») увеличивает шрифт на 12,5% или
  25%. Применяет ли MAX на Android системный масштаб шрифта к мини-приложению,
  мы не проверяли: если применяет, увеличения сложатся. Подписи таб-бара
  кабинета УК на узком экране не растут, иначе шесть вкладок не помещаются.

## Остановка и повторный запуск

```sh
docker compose stop             # остановить, контейнеры и данные остаются
docker compose start            # запустить остановленные контейнеры
docker compose down             # удалить контейнеры, база и Redis остаются в томах
docker compose up -d --build    # поднять заново, миграции прогонятся сами
docker compose down -v          # удалить и тома: база пустая, нужно заново заполнить
```

После `docker compose down -v` демо-данные нужно заполнить заново, как в
разделе «Тестовые данные». Фото лежат в `backend/content` на диске хоста и
вместе с томами не удаляются.

ИИ-ассистент (Claude Code) помогал в разработке: писал код по планам

(Yandex SpeechKit), см. «Внешние сервисы».

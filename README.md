# Жэка Коммуналкин

Чат-бот с мини-приложением в MAX, через который жители многоквартирных домов общаются со своей управляющей компанией. Трек «Умный город», команда «Мобилизация»

Бот: https://max.ru/t260_hakaton_max_bot

Документация: [продукт](docs/product.md), [архитектура](docs/architecture.md), [данные](docs/data.md), [маршрут проверки по всем возможностям](docs/features/00-route.md)

## Назначение

Когда в доме протечка, сломался лифт или не вывезли мусор, житель часто не знает, кому сообщить, а потом не видит, что стало с обращением. С 1 сентября 2026 года УК обязаны обеспечить взаимодействие с жителями, в том числе через MAX (ПП РФ от 26.01.2026 № 40). Мы предполагаем, что готового инструмента для этого у многих УК нет

Житель находит в Жэке свой дом, подает заявку с фото, видит ее статус и срок, а бот сообщает о каждом изменении. Там же он передает показания счетчиков, смотрит начисления и карточку дома, голосует в опросах. Сотрудник УК в кабинете УК принимает заявки, меняет статусы, назначает исполнителей, видит аналитику по своим домам и публикует объявления в домовые чаты. Бот один на все УК, поэтому у жителя один вход, какая бы УК ни управляла его домом

CustDev: мы опросили друзей и родственников и вместе с ними сравнили Госуслуги Дом и Жэку. Вывод - в Жэке больше функций прямо внутри MAX, чем в Госуслугах Дом

## Основной сценарий

1. Житель открывает бота и соглашается на обработку персональных данных
2. Находит свой дом: город, улица и дом, геопозиция или ссылка из домового чата
3. Подает заявку с описанием, категорией, местом проблемы (в квартире или в доме) и фото и сразу получает номер и срок. В мини-приложении категорию по описанию может подсказать модель, если заданы ключи Yandex
4. Бот сообщает сотруднику УК о новой заявке, сотрудник принимает ее и ведет по статусам. Житель получает уведомление на каждом шаге, кнопка в нем открывает заявку в мини-приложении
5. Житель подтверждает квартиру и передает показания счетчиков по фото, видит расход и сравнение со средним по дому
6. Когда заявку выполнили, житель ставит оценку. Если сделано плохо, подает повторную заявку с фото и ссылкой на старую

В боте короткие диалоги, уведомления и напоминания. Формы, списки, графики и кабинет УК - в мини-приложении, оно открывается кнопкой «📱 Открыть приложение» под меню бота

## Что мы считаем уникальным?

- [Прогноз кворума по площади](docs/features/59-polls.md): опрос дома считает голоса собственников по площади квартир, как на общем собрании, и показывает, сколько не хватает до 50%
- [Окна доступа в квартиры](docs/features/63-access-requests.md): для замены стояка или поверки УК один раз задает окна, жители сами выбирают время, сотрудник видит «ответили 9 из 14»
- [Реестр уведомлений](docs/features/58-notice-register.md) и [отчет о доставке](docs/features/57-delivery-report.md): каким квартирам MAX доставил объявление или приглашение к опросу, лист A4 и PDF с квартирами для бумажного уведомления
- [«Мне нужен» на доме без УК](docs/features/17-not-connected-house.md): жители зовут свою УК в сервис, а [подключенные УК видят](docs/features/73-unconnected-houses.md) дома, где сервиса ждут
- [Список закрепов в чате дома](docs/features/41-house-chat.md): MAX закрепляет одно сообщение, бот ведет нумерованный список командами `/pin`, `/unpin N`, `/repin`
- [Вопрос по строке квитанции](docs/features/53-charge-question.md): заявка сама собирает услугу, период, сумму, расчет и изменение к прошлому месяцу
- [Заявка по звонку](docs/features/30-request-by-phone.md): диспетчер заводит звонок в тот же конвейер со сроком, статусами и приемкой
- [Недельная сводка дома](docs/features/66-weekly-digest.md): по воскресеньям заявки, объявления, опросы и окно показаний одним сообщением
- [Три уровня уведомлений](docs/features/65-notification-settings.md): каждую категорию можно получать со звуком, без звука или выключить
- [Расход в сравнении со средним по дому](docs/features/47-meters.md) после каждой передачи показаний


## Состав и архитектура

```
MAX ──HTTPS──> TLS на хосте ──> nginx :80 ─┬─ /          ─> web        статика мини-приложения
                                           ├─ /api/      ─> api        FastAPI + бот
                                           ├─ /files/    ─> api        загруженные фото
                                           ├─ /tiles/    ─> кэш nginx  подложки карты: OpenFreeMap, OSM
                                           └─ = /webhook ─> api        вебхук бота

api, worker ──> database (PostgreSQL 16)
            └─> redis (FSM бота, очередь и расписание taskiq)
```

| Сервис | Что делает |
|---|---|
| `web` | Мини-приложение: React + TypeScript, `@maxhub/max-ui`, MAX Bridge. Статика, которую отдает nginx внутри образа |
| `api` | FastAPI под gunicorn: REST для мини-приложения и бот на `maxo` в том же процессе, в режиме `polling` или `webhook` |
| `worker` | Фоновые задачи taskiq и расписание: уведомления, сообщения в домовые чаты, напоминания, контроль сроков заявок, автозакрытие, очистка старых файлов |
| `migrations` | Прогоняет миграции alembic и завершается. Он же собирает образ бэкенда для `api` и `worker` |
| `database` | PostgreSQL 16 |
| `redis` | Redis 7 |
| `nginx` | Единственная точка входа, разводит запросы по путям |

Код: `backend/zheka/bot` - бот, `backend/zheka/api` - REST, `backend/zheka/core` - доменные модели и сервисы, `backend/zheka/infra` - база, клиент MAX, Yandex, `backend/zheka/broker` - фоновые задачи, `backend/zheka/seed` - демо-данные, `frontend/src` - мини-приложение

Мини-приложение авторизуется подписанным `initData` из MAX, для проверки API без MAX есть тестовый токен (см. «Проверка API»). Данные разных УК разделены: на заявку чужой УК сотрудник получает 404. Подробнее - в [docs/architecture.md](docs/architecture.md)

## Запуск

Нужен Docker с Compose v2. Токен бота MAX (`MAX_TOKEN`) нужен только самому боту: для проверки API локально хватает заглушки из `.env.example`

```sh
cp .env.example .env    # для бота вписать MAX_TOKEN
docker compose up -d --build
```

Compose соберет образы, прогонит миграции и поднимет все сервисы. Первый запуск занимает около минуты без учета скачивания базовых образов. Проверка готовности:

```sh
curl http://localhost/api/healthcheck
```

Заполнить пустую базу демо-данными:

```sh
docker compose run --rm api python -m zheka.seed
```

Чтобы проверять API локально запросами, впишите в `.env` любой `API_TEST_TOKEN`, например `API_TEST_TOKEN=local`, и пересоздайте `api` командой `docker compose up -d api`. Запросы из «Проверки API» тогда работают с `http://localhost/api` и заголовком `Authorization: Bearer local`. Id в `DATA-API.yaml` (дом 1061, квартира 16714, заявка 10853) есть только на стенде: локально дом и квартира - `house_id` и `flat_id` из `residency` в ответе `POST /api/demo/activate`, своя заявка - `id` из ответа `POST /api/requests`

Бот локально работает в режиме `polling`, домен и сертификат не нужны. Токен берите отдельный, тестовый: пока на проде включен вебхук, long polling с тем же токеном обновлений не получит

С заглушкой токена из `.env.example` поднимается все, кроме бота: API, `/api/docs`, статика, миграции и заполнение базы работают. В логе `api` будет ERROR о том, что MAX отверг токен, в логе `worker` - та же ошибка на каждое уведомление

Мини-приложение MAX открывает только по публичному HTTPS-адресу из настроек бота, поэтому локальную сборку в MAX не увидеть: мини-приложение проверяйте на развернутом боте

## Окружение

Все переменные с комментариями лежат в `.env.example`, compose читает `.env` из корня репозитория

| Переменная | Обязательна | Назначение |
|---|---|---|
| `MAX_TOKEN` | да | Токен бота MAX |
| `MAX_BOT_MODE` | нет | `polling` (по умолчанию, локально) или `webhook` (прод) |
| `MAX_WEBHOOK_URL` | при `webhook` | Публичный HTTPS-адрес вебхука, `https://<домен>/webhook` |
| `MAX_SECRET_TOKEN` | при `webhook` | Секрет вебхука, сверяется с заголовком `X-Max-Bot-Api-Secret` |
| `DEEPLINK_ORG_REGISTER` | да | Скрытый код регистрации УК: 1-64 символа из латиницы, цифр, `_` и `-` |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | да | Учетные данные PostgreSQL |
| `POSTGRES_HOST`, `POSTGRES_PORT` | вне Docker | Адрес PostgreSQL, в compose зафиксирован |
| `REDIS_PASSWORD` | да | Пароль Redis |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB` | вне Docker | Адрес Redis, в compose зафиксирован |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | нет | Yandex Vision OCR, AI Studio и SpeechKit. Без них продукт работает, но без подсказок |
| `YANDEX_MODEL` | нет | Текстовая модель AI Studio, по умолчанию `yandexgpt-5-lite` |
| `FILES_MAX_SIZE_MB` | нет | Предельный размер фото, по умолчанию 10 |
| `FILES_MAX_VIDEO_MB` | нет | Предельный размер видео, по умолчанию 50 |
| `FILES_DIR` | вне Docker | Каталог файлов, в compose это `/data/files` |
| `API_CORS` | нет | Разрешенные источники через запятую, пусто - все. На проде `https://vkmax.k1rles.ru` |
| `API_TEST_TOKEN` | нет | Тестовый токен для API без MAX, заголовок `Authorization: Bearer <токен>`. Пусто - выключено |
| `API_HOST`, `API_PORT` | вне Docker | Адрес gunicorn, в compose `0.0.0.0:7001` |
| `LOG_LEVEL`, `LOG_FORMAT` | нет | Уровень логов и формат: `PLAIN` локально, `JSON` на проде |
| `NGINX_PORT` | нет | Порт nginx на хосте, по умолчанию 80 |
| `BUILD_COMMIT` | нет | Коммит сборки в ответе `/api/healthcheck`, по умолчанию `dev`. В `.env` его нет: деплой передает `git rev-parse HEAD` в сборку образа |

| Порт | Где | Кто |
|---|---|---|

## Внешние сервисы

| Сервис | Зачем | Без него |
|---|---|---|
| MAX Bot API | Бот, уведомления, мини-приложение | Не работает ничего |
| Yandex Vision OCR | Показание счетчика по фото | Житель вводит показание руками |
| Yandex AI Studio | Подсказка категории заявки и вероятности аварии | Житель выбирает категорию кнопками, опасные фразы ловят правила без модели |
| Yandex SpeechKit | Расшифровка голосового в боте, если MAX не прислал свою | Бот просит написать текстом |
| OpenFreeMap, OpenStreetMap | Подложки карты через кэширующий прокси `/tiles/` | Карта не грузится, выбор дома остается списком |
| Nominatim (OpenStreetMap) | Адрес здания по тапу на карте | Тап по дому не из справочника не показывает адрес |

MAX Bot API в Docker не воспроизвести: для проверки нужен токен бота, а для мини-приложения - развернутый бот (ссылка выше). Сервисы Yandex необязательны. Модель только предлагает категорию, житель может выбрать другую. ГИС ЖКХ API не вызывает: паспорт дома собран заранее, при подготовке демо-данных. Оплаты нет, платеж в мини-приложении демонстрационный

## Данные

Храним пользователей MAX и их согласие на обработку персональных данных (версию и дату), дома, квартиры и лицевые счета, заявки с фото, показания, начисления, опросы, объявления и события для аналитики. Пока житель не дал согласие, ни бот, ни мини-приложение дальше не пускают. Персональные данные жителя видит только УК его дома

Фото и PDF лежат на диске в `backend/content` под UUID-именами, ссылку на файл API подписывает на час и выдает только тем, кому файл положено видеть. PostgreSQL и Redis живут в томах `<проект>_zheka-postgres` и `<проект>_zheka-redis`, кэш тайлов - в `<проект>_zheka-tiles`, где проект - имя папки репозитория

Реальные данные: дома и управляющие организации - открытые данные Реформы ЖКХ (reformagkh.ru), кадастровый номер, износ, состояние и класс энергоэффективности - публичная часть ГИС ЖКХ (dom.gosuslugi.ru), координаты - © участники OpenStreetMap (ODbL 1.0), телефоны городских служб «Куда звонить» для Москвы, Санкт-Петербурга и Казани - официальные сайты, сверены 29.09.2026

Модельные данные: организации «Демо-УК ...», их сотрудники, жители, начисления, показания, заявки, опросы, объявления и документы. В мини-приложении такие разделы помечены как модельные. Источники и выгрузки - в [docs/data.md](docs/data.md)

## Тестовые данные

`python -m zheka.seed` заполняет пустую базу одной транзакцией: справочник домов и 17 демо-УК в трех городах с историей за полгода. На развернутом боте то же делает команда `/seed` в личке с ботом

История заканчивается днем заполнения, а дашборд и сравнение с другими УК считают последние 30 дней, поэтому базу лучше заполнять ближе к проверке. Заполнить повторно можно только пересозданную базу: `docker compose down -v`, затем запуск и заполнение

### Демо-доступ

В MAX у каждого свой аккаунт, поэтому «логин жителя» выдать нельзя. Роль выдает ссылка в бота с параметром `start`:

```
https://max.ru/t260_hakaton_max_bot?start=demo_resident_1
```

| Параметр | Что выдает |
|---|---|
| `demo_resident_N` | Собственную подтвержденную квартиру в первом доме демо-УК N с начислениями и показаниями за полгода и арендатором |
| `demo_staff_N` | Роль сотрудника демо-УК N |
| `demo_admin_N` | Роль администратора демо-УК N |
| `demo_executor_N` | Роль исполнителя демо-УК N вместо сотрудника или администратора. На вас назначается последняя новая или принятая заявка вашей демо-квартиры. Роль сотрудника возвращает `demo_staff_N` |

N от 1 до 4, демо-УК №5 отведена под проверку API. У каждого проверяющего-жителя своя квартира, но сотрудники одной демо-УК видят общие входящие заявки: для независимой проверки берите разные N. Один аккаунт может пройти по нескольким ссылкам и получить несколько ролей. Если база не заполнена, ссылка ответит «Демо-доступ еще не готов»

Демо-УК общая для всех проверяющих: ее настройки, исполнители по категориям и часы приема открыты только для чтения, а действия над чужими проверяющими (блокировка, снятие подтверждения, отзыв чужого приглашения) запрещены

Лицевой счет у квартир демо-УК - номер квартиры, дополненный нулями до 10 цифр: у кв. 12 это `0000000012`. С ним можно подтвердить любую квартиру, кроме квартир проверяющих `Д...`: они подтверждены сразу. Для подтверждения по QR подходит [`docs/demo-receipt-qr.png`](docs/demo-receipt-qr.png) (кв. 12 любого дома демо-УК)

## Сценарий проверки

Короткий маршрут ниже. Полный, по всем 76 возможностям, - в [docs/features/00-route.md](docs/features/00-route.md)

1. Откройте `https://max.ru/t260_hakaton_max_bot?start=demo_resident_1` и дайте согласие на обработку данных
2. Бот ответит «🎫 Демо-доступ открыт: ваша квартира ...». Откройте приложение кнопкой «📱 Открыть приложение»
3. Во вкладке «Заявки» подайте заявку о протечке: опишите проблему, укажите, где она, приложите фото. Заявка появится с номером, статусом и сроком
4. Под сроком раскройте «Демо для проверки» и нажмите «Демо: срок истек» (кнопка есть только в демо-УК). Бот пришлет «🔴 Срок по заявке ... истек» с кнопкой «📄 Жалоба в ГЖИ». В карточке заявки появится блок эскалации: «Попросить руководство УК», «Получить PDF в чат с ботом» (в чат придет `zhaloba-N.pdf` с пометкой «ДЕМО») и «3. Куда ещё» с адресатами по категории
5. В Профиле откройте карточку дома: УК, «Куда звонить», перечень работ по ПП РФ № 290 («Показать перечень работ»), тарифы, капремонт, документы
6. На Главной нажмите «Передать» и передайте показание с фото счетчика: значение распознается или вводится вручную, приложение покажет расход и сравнение со средним по дому
7. Тем же аккаунтом откройте `https://max.ru/t260_hakaton_max_bot?start=demo_staff_1`. Бот даст кнопку «🧑‍💼 Открыть кабинет УК». Сообщение о новой заявке автору не приходит: чтобы его увидеть, откройте эту ссылку вторым аккаунтом до шага 3
8. В кабинете УК во вкладке «Заявки» выберите в фильтре «Статус» значение «Новые» и откройте свою заявку. В «Переписке с жителем» включите «Нужен ответ жителя» и задайте вопрос: вам как автору придет «❓ УК уточняет по заявке ...», ответьте через «📝 Ответить»
9. Примите заявку в работу, начните работы и отправьте на приемку. На каждую смену статуса бот пишет жителю с кнопкой «📱 Открыть заявку», на приемке приходит карточка с фото: работу можно принять и оценить в чате или вернуть кнопкой «👎 Сделано плохо»
10. Откройте вкладку «Аналитика» кабинета УК: дашборд по домам организации
11. Подайте еще одну заявку и откройте `https://max.ru/t260_hakaton_max_bot?start=demo_executor_1`. Бот пришлет карточку заявки: нажмите «🚗 Выехал», затем «🏁 Готово» и пришлите фото результата. Вернуть роль сотрудника - ссылкой `demo_staff_1`

Напоминания (показания, поверка, опросы, запись на прием) бот шлет по расписанию. Чтобы не ждать, отправьте боту `/demo`: он сразу пришлет по одному напоминанию каждого вида. Коллективную заявку с одного аккаунта собирает кнопка «Демо: соседи сообщили» на своей открытой заявке

## Проверка API

Собственный API решения: `https://vkmax.k1rles.ru/api`. Контракт - `openapi.yaml` (OpenAPI 3.1), обязательные проверки - `DATA-API.yaml` по схеме DATA-API 1.0. Их соответствие проверяет `backend/tests/test_data_api.py`

`initData` вне MAX не получить, поэтому для проверки есть тестовый токен в заголовке `Authorization: Bearer <токен>`. Он записан в `DATA-API.yaml` в каждой проверке с ролями `resident` и `staff`, проверки `public` идут без него. Токен открывает одну учетную запись «Проверяющий API». Первые две проверки в `DATA-API.yaml` дают согласие и демо-доступ к демо-УК №5 (квартира и роль сотрудника), обе можно повторять. Токен не пускают в другие демо-УК и к роли администратора (403). Проверки заявок передают `X-House-Id`: житель нескольких домов без него получает 403

```sh
TOKEN=$(grep -m1 -o 'Bearer [0-9a-f]*' DATA-API.yaml | cut -d' ' -f2)
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"version":"1.2"}' https://vkmax.k1rles.ru/api/me/consent
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":5}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" https://vkmax.k1rles.ru/api/me
```

Стенд отвечает, из какого коммита собран; `commit` совпадает с хэшем на служебном слайде, локальная сборка отвечает `dev`:

```sh
curl https://vkmax.k1rles.ru/api/healthcheck
# {"ok":true,"commit":"<хэш>"}
```

Отказы приходят в конверте `{"status", "ok": false, "trace_id", "error": {"title", "detail"}}`, причина - в `error.detail`:

| Действие | Код | Текст |
|---|---|---|
| `GET /api/me` без `initData` и токена | 401 | «Нужна initData в заголовке WebAppData или тестовый токен» |
| Чужая заявка, `GET /api/requests/1` с токеном | 404 | «Заявка не найдена» |
| Токен и `POST /api/demo/activate` с `{"number":1}` | 403 | «Тестовый токен получает только роль сотрудника демо-УК №5» |
| Исполнитель обращается к API кабинета УК | 403 | «Исполнитель работает только через бота» |
| Статус заявки назад, `POST /api/admin/requests/{id}/status` с `{"status":"accepted"}` для закрытой заявки другого жителя из сида. Свои заявки токен ведет только до «Принята», дальше - 403 | 409 | «Статус заявки назад не двигается» |
| Не изображение и не видео по содержимому, даже с `type=image/jpeg`, в `POST /api/files` | 400 | «Поддерживаются только изображения и видео MP4 или MOV» |
| Фото больше 10 МБ в `POST /api/files` | 400 | «Файл больше 10 МБ» |
| 31-я загрузка за час | 429 | «Слишком много запросов, попробуйте позже» |
| Тело не по схеме, `{"number":9}` в `POST /api/demo/activate` | 400, не 422 | «Поле: ('body', 'number')» и тип ошибки `less_than_equal` |
| Администратор демо-УК меняет ее настройки, `PUT /api/admin/org/settings`. Проверяется в MAX ролью `demo_admin_N`: тестовый токен - сотрудник и получит «Нужны права администратора организации» | 403 | «Демо-УК общая для всех проверяющих, это действие в ней отключено» |
| `POST /webhook` без заголовка `X-Max-Bot-Api-Secret`, только на стенде: локально бот в режиме `polling`, маршрута нет и ответ 404 | 403 | `{"detail":"Forbidden"}` от maxo, без конверта |

Строки с токеном - после команд выше:

```sh
TOKEN=$(grep -m1 -o 'Bearer [0-9a-f]*' DATA-API.yaml | cut -d' ' -f2)
curl https://vkmax.k1rles.ru/api/me
curl -H "Authorization: Bearer $TOKEN" https://vkmax.k1rles.ru/api/requests/1
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":1}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"number":9}' https://vkmax.k1rles.ru/api/demo/activate
curl -H "Authorization: Bearer $TOKEN" -F "file=@README.md;type=image/jpeg" \
  https://vkmax.k1rles.ru/api/files
ID=$(curl -s -H "Authorization: Bearer $TOKEN" \
  "https://vkmax.k1rles.ru/api/admin/requests?status=done&limit=1" | grep -o '"id":[0-9]*' | head -1 | cut -d: -f2)
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"status":"accepted"}' https://vkmax.k1rles.ru/api/admin/requests/$ID/status
curl -X POST -d '{}' https://vkmax.k1rles.ru/webhook
```

С 30.09 по 29.10 `.github/workflows/uptime.yml` проверяет healthcheck и коммит, главную страницу и отказ вебхука без секрета (до 14.10 раз в 15 минут, потом раз в час) и при сбое пишет капитану в MAX

## Ожидаемое поведение

- `/start` без параметров открывает меню «👋 Жэка Коммуналкин на связи»: пока дом не выбран, в нем «🔎 Найти дом», «📝 Подать заявку» и «📱 Открыть приложение». Сотруднику УК меню дает кнопку «🧑‍💼 Открыть кабинет УК»
- Без согласия на обработку данных бот показывает только экран согласия. `/help` описывает, что умеет бот, и выводит список команд, `/faq` отвечает на частые вопросы
- О новой заявке сотрудники УК получают сообщение с кнопкой в кабинет УК, автору оно не приходит. На каждую смену статуса бот пишет жителю
- Когда до конца срока остается четверть (от 1 до 24 часов), сотрудникам и исполнителю приходит «⏳ ... осталось N ч». После срока им приходит «🔴 ... просрочена», жителю - сообщение с кнопкой «📄 Жалоба в ГЖИ». Каждое сообщение уходит один раз
- Просьба жителя к руководству УК: сотрудники и исполнитель получают «📢 Житель просит руководство вмешаться», житель - «📢 Руководство УК уведомлено ...». Один раз на заявку
- Отмена жителем до приемки: сотрудники и исполнитель получают «↩️ Житель отменил заявку ...» с причиной. Заявку на приемке или закрытую отменить нельзя
- Сообщение с опасной фразой («Пахнет газом») открывает в боте экран аварии, уведомление сотрудникам начинается с «🚨 Опасность: ...»
- Неразобранное сообщение: «🤔 Не понял сообщение, вот что я умею» и меню. Кнопка в старом сообщении: «🔄 Это окно устарело, открываю меню заново». Неожиданная ошибка: «❗ Что-то пошло не так, попробуйте еще раз» и меню
- Показание меньше предыдущего: «Новое значение меньше предыдущего, уточните показание». Показание не за текущий период или за период с выставленной квитанцией отклоняется с причиной
- Без ключей Yandex распознавание возвращает пустое значение, подсказка категории - `null`, житель заполняет поля сам. Опасные фразы правила ловят и без ключей
- `GET /api/healthcheck` отвечает 200 с `ok` и `commit`, документация API - `/api/docs`. Запрос без `initData` и токена получает 401 с причиной

## Известные ограничения

- Полноценного пилота не было: CustDev прошел только на друзьях и родственниках
- HTTPS в репозитории не настроен: на проде TLS завершает nginx на хосте перед compose
- Обмена с ГИС ЖКХ нет, начисления и оплата модельные
- Регистрацию УК подтверждает только скрытый код `DEEPLINK_ORG_REGISTER`, без ЕСИА
- Бот не может написать жителю первым, если тот ни разу его не открывал, и сам не создает домовые чаты
- MAX ограничивает бота 30 запросами в секунду: рассылка тысяче жителей занимает около 35 секунд
- Через 30 дней после заполнения базы дашборд и сравнение с другими УК пустеют
- Лимиты в час на пользователя (60 вызовов Yandex, 30 загрузок файлов, 10 подтверждений квартиры, 5 новых домов и 60 адресов на карте) считаются в памяти каждого воркера `api`
- Тип файла сервер определяет по первым байтам и изображение не декодирует; AVIF и старые MOV без `ftyp` отклоняются
- Опасные фразы ловят короткие правила, модель помогает только с ключом Yandex
- Сроки лифта, мусора, подъезда и двора - сроки сервиса, нормы под ними нет; срок реакции есть только у протечки
- Производственный календарь статичный, праздники и переносы заданы по 2027 год
- Паспорт дома обновляется только пересевом, у дома, добавленного жителем, паспорта нет
- «Куда звонить» есть только в Москве, Санкт-Петербурге и Казани
- Жалоба в ГЖИ в PDF - черновик без ФИО и адреса, приходит только в чат с ботом
- Сканер QR квитанции есть только в MAX на iOS и Android и на живых телефонах не проверен
- Реестр уведомлений фиксирует, что MAX принял сообщение, а не что его прочитали
- Юридически значимое общее собрание бот не проводит: опросы только собирают мнения
- Привязаться к дому, подать заявку и записаться на прием можно без подтверждения квартиры; начисления, счетчики и голос с весом площади - только после него

## Остановка и повторный запуск

```sh
docker compose stop             # остановить, контейнеры и данные остаются
docker compose start            # запустить остановленные контейнеры
docker compose down             # удалить контейнеры, база и Redis остаются в томах
docker compose up -d --build    # поднять заново, миграции прогонятся сами
docker compose down -v          # удалить и тома: база пустая, нужно заново заполнить
```

После `docker compose down -v` демо-данные нужно заполнить заново (см. «Тестовые данные»). Фото лежат в `backend/content` на хосте и вместе с томами не удаляются

## Возможности MAX сверх минимума

- Домовые чаты: бот привязывается к чату дома, публикует туда объявления из кабинета УК и ведет список закрепов. Проверка одним аккаунтом: получите роль по `demo_staff_1`, создайте группу в MAX и добавьте бота, он спросит в личке, к какому дому привязать чат. Объявление из вкладки «Объявления» кабинета УК придет в чат, `/pin` в ответ на сообщение добавит его в закрепы
- Бот и мини-приложение связаны: уведомления открывают заявку в приложении или кабинете УК, ссылки `?start=` из QR, приглашений и демо-доступа сразу выбирают дом, организацию или роль
- Приемку с фото, оценку и повторную заявку житель делает прямо в чате. Исполнитель ведет заявку кнопками бота без мини-приложения
- QR на подъезд: роль по `demo_admin_1`, в кабинете УК «Дома» - дом - QR
- Подтверждение квартиры платежным QR с квитанции через сканер MAX: сервер берет из QR только лицевой счет (`persAcc`)
- Уведомления настраиваются по категориям: со звуком, без звука, выключены

## Обращения и ПП РФ № 416

Работа с заявками сверена с Правилами управления МКД (ПП РФ от 15.05.2013 № 416) в редакции от 20.06.2026: обращение идет через MAX и ответ тем же каналом (п. 35), номер и срок житель получает сразу (п. 17(2)), запрос и ответ хранятся 3 года, заявки не удаляются (п. 38). Срок записывается в заявку при подаче и считается от нее, под ним указано основание. У воды, отопления и света норма задает допустимый перерыв, а не срок заявки:

| Категория | Локализовать аварию | Выполнить | Основание: что задает норма |
|---|---|---|---|
| Протечка | 30 минут | 3 суток | ПП РФ № 416, п. 13: локализовать аварию за 30 минут с регистрации заявки, устранить не более чем за 3 суток с даты аварии |
| Водоснабжение | - | 4 часа | ПП РФ № 354, прил. 1, п. 1, 4: допустимый перерыв 4 часа подряд и 8 часов за месяц |
| Отопление | - | 16 часов | ПП РФ № 354, прил. 1, п. 14: допустимый перерыв 16 часов подряд, если в квартире не ниже +12 °C, и 24 часа за месяц |
| Электричество | - | 24 часа | ПП РФ № 354, прил. 1, п. 9: допустимый перерыв 24 часа при одном источнике питания, 2 часа при двух |
| Лифт, мусор | - | 24 часа | срок сервиса; засор мусоропровода ПП РФ № 416, п. 13 велит ликвидировать за 2 часа, но категория шире засора |
| Подъезд, двор | - | 3 суток | срок сервиса |
| Ошибка в показаниях | - | 10 рабочих дней | ПП РФ № 354, п. 31 «е(2)»: проверить счетчик не позднее 10 рабочих дней со дня заявления |
| Спор по начислению | - | 10 рабочих дней | ПП РФ № 416, п. 36 |
| Другое | - | 10 рабочих дней | ПП РФ № 416, п. 36 |

Рабочие дни считаются со дня после подачи по времени дома. Заявка ссылается на пункты минимального перечня работ (ПП РФ № 290) своей категории, а просроченная - называет адресатов жалобы с темами справочника НСИ 220 ГИС ЖКХ. Подробнее: [сроки](docs/features/21-deadline-norms.md), [жалоба и адресаты](docs/features/37-gji-complaint.md), тексты норм - [ПП РФ № 354, п. 31](docs/norms/pp354-p31.md), [ПП РФ № 416, пп. 34-37](docs/norms/pp416-p34-37.md)

## Использование ИИ

ИИ-ассистент (Claude Code) помогал в разработке: писал код по планам команды и по ее правилам из `backend/AGENTS.md` и `frontend/AGENTS.md`. Продуктовые решения, архитектуру, планы, проверку кода и сценариев команда оставила за собой. Результат ассистента проверяют тесты, строгая типизация и линтеры

В коде продукта ИИ умеет три вещи: подсказать категорию заявки и вероятность аварии (Yandex AI Studio), распознать показания (Yandex Vision OCR) и расшифровать голосовые (Yandex SpeechKit). Все три работают только с ключами Yandex

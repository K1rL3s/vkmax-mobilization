# Защита демо-стенда

Демо-УК общие для всех проверяющих сразу, поэтому один проверяющий не должен сломать демо другому: заблокировать чужую демо-квартиру, снять с нее подтверждение, перенастроить УК или исключить коллегу из команды. Тестовому токену DATA-API отведены одна демо-УК и своя роль, остальное ему закрыто.

## Как работает

- В демо-УК заблокировать жителя или отозвать подтверждение его квартиры можно только у себя самого или у модельного жителя (без реального аккаунта MAX за ним): попытка ограничить настоящего проверяющего дает отказ «В демо-УК можно ограничить только модельных жителей». Председателя дома снять или сменить можно только модельного или себя, иначе «В демо-УК можно снять или сменить только модельного председателя».
- Настройки демо-УК, исполнители по категориям и часы приема открыты только для чтения, исключить сотрудника нельзя. В интерфейсе поля настроек неактивны, «Сохранить настройки» не нажимается, строки «Исполнители по категориям» без стрелки, под ними подсказка «В демо-УК настройки общие для всех проверяющих и не меняются»; в «Команде» нет кнопок исключения и написано «В демо-УК команда общая для всех проверяющих, исключить никого нельзя»; сводка «Часы приёма» не раскрывается. API тоже отказывает: `PUT /api/admin/org/settings`, `DELETE /api/admin/org/members/{user_id}`, `PUT /api/admin/org/category-executors` и `PUT /api/admin/reception/windows` в демо-УК отвечают 403 «Демо-УК общая для всех проверяющих, это действие в ней отключено». В УК, зарегистрированной по коду, все сохраняется как раньше.
- Приглашение в демо-УК отозвать можно только свое: чужое отвечает тем же «Демо-УК общая для всех проверяющих, это действие в ней отключено». Так же досрочно завершаются только свои плановые работы: засеянная «Опрессовка» и работы других проверяющих остаются идти (файл 56).
- Порог склейки демо-УК остается 10 квартир за сутки, поэтому заявки проверяющих из первого дома не склеиваются с чужими, а коллективную заявку с одного аккаунта собирает кнопка «Демо: соседи сообщили» (файл 42). Сотрудник по `demo_staff_1` после любых действий администратора остается в команде.
- Демо-УК №5 отведена под тестовый токен DATA-API: ссылок `demo_admin_5` и `demo_staff_5` для живого аккаунта нет, попытка занять эту организацию другим способом дает «Демо-УК №5 отведена под проверку API, выберите другую».
- Сам тестовый токен, наоборот, не может выйти за пределы демо-УК №5 и роли сотрудника: запрос демо-доступа с другим номером организации или с ролью администратора отвечает «Тестовый токен получает только роль сотрудника демо-УК №5».

## Как проверить

Перед началом: два аккаунта в одной демо-УК (аккаунт А и аккаунт Б, или два реальных проверяющих с одинаковым N), плюс тестовый токен из README «Проверка API».

1. Аккаунтом Б (роль администратора `demo_admin_1`) попробуйте заблокировать жителя, который принадлежит другому реальному проверяющему той же демо-УК (например, привязанного через `demo_resident_1` на другом устройстве) - отказ «В демо-УК можно ограничить только модельных жителей». Модельных жителей (без своего лицевого счета `Д...`) блокировать можно как обычно.
2. Тем же аккаунтом откройте «Дома» -> «Организация и сотрудники» - поля настроек неактивны, под «Сохранить настройки» и под «Исполнителями по категориям» подсказка «В демо-УК настройки общие для всех проверяющих и не меняются», в «Команде» нет кнопок исключения.
3. Откройте вкладку «Приём» -> «Часы приёма» - сводка расписания видна, но не раскрывается, вместо «Изменить» та же подсказка.
4. «Организация и сотрудники» -> «Приглашения» -> создайте ссылку, откройте ее и нажмите «Отозвать» - статус станет «Отозвано». Чужое приглашение отозвать нельзя: в окне появится «Демо-УК общая для всех проверяющих, это действие в ней отключено».
5. Через curl отправьте `POST /demo/activate` с телом `{"number": 1}` тестовым токеном - отказ «Тестовый токен получает только роль сотрудника демо-УК №5».
6. Тем же токеном отправьте `{"number": 5}` - демо-доступ откроется без ошибки, это единственная разрешенная ему организация.

## Ограничения

- Защиту демо-УК №5 от живого аккаунта в боте не проверить: демо-ссылки на нее нет, остается читать код.
- 403 на запись настроек демо-УК через API видит только администратор: тестовый токен - сотрудник, и ему те же запросы отвечают «Нужны права администратора организации».
- Сохранить настройки проверяющий не может ни в одной УК: свою он без скрытого кода не зарегистрирует. Модельного исполнителя тоже нельзя исключить. Перевыпуск кода привязки чата и ручное напоминание о показаниях в демо-УК не закрыты: это безвредно.

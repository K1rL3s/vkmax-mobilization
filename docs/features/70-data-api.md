# Проверка через DATA-API

Мини-приложение работает поверх собственного API, задокументированного в `openapi.yaml`, а обязательный набор проверок для хакатона описан в `DATA-API.yaml` по схеме организаторов DATA-API 1.0. initData вне MAX не получить, поэтому для проверки есть отдельный тестовый токен: он дает прямой доступ к API, но не заменяет живой сценарий в боте.

## Как работает

- Заголовок `Authorization: Bearer 34c63235dea4b1fb95ce89a9f108fc18` открывает одну служебную учетную запись «Проверяющий API» с ролями resident и staff; проверки с ролью public идут без токена. Самого токена в `DATA-API.yaml` нет, он передается отдельно.
- Первые две проверки в `DATA-API.yaml` дают этой записи согласие и демо-доступ, после чего у нее есть квартира в демо-УК №5 и роль сотрудника этой УК. Демо-УК №5 отведена только под токен (см. 68-demo-guard.md), поэтому его действия не пересекаются с действиями жюри в демо-УК №1.
- Токен ведет свою тестовую заявку только до статуса «Принята»: на ней держится проверка `staff_status`, которая сама переводит заявку в этот статус. Дальше него токен ее не двигает - отказ «Тестовый токен ведет свои заявки только до статуса «Принята»: на них держатся обязательные проверки API». Засеянные заявки демо-УК №5 токен ведет по всем статусам.
- `GET /api/healthcheck` не требует авторизации и отвечает `{"ok": true}`; при недоступной базе - ошибка сервера.
- Соответствие путей `openapi.yaml` и `DATA-API.yaml` проверяет тест `backend/tests/test_data_api.py` - это часть CI, а не то, что видно в проде.

## Как проверить

Перед началом: продовый адрес API `https://vkmax.k1rles.ru/api`, тестовый токен `34c63235dea4b1fb95ce89a9f108fc18`.

1. Выполните команды из README «Проверка API»:
   ```sh
   TOKEN=34c63235dea4b1fb95ce89a9f108fc18
   curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     -d '{"version":"1.1"}' https://vkmax.k1rles.ru/api/me/consent
   curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     -d '{"number":5}' https://vkmax.k1rles.ru/api/demo/activate
   curl -H "Authorization: Bearer $TOKEN" https://vkmax.k1rles.ru/api/me
   ```
   Третья команда должна вернуть профиль с именем «Проверяющий API».
2. Без заголовка `Authorization` выполните `curl https://vkmax.k1rles.ru/api/healthcheck` - ответ `{"ok": true}` без токена.
3. Повторите первые две команды из шага 1 еще раз - обе проверки идемпотентны и повторяются без ошибок.

# Открытые данные ЖКХ: что реально взять в сид

Откуда брать реальные данные для «Жеки Коммуналкина» по Москве,
Санкт-Петербургу и Казани. Источники проверены 16.09.2026: URL и цифры ниже
получены загрузкой, кроме помеченных как вывод или непроверенное.

Схема данных, к которой все привязано: `houses`, `flats`, `organizations`,
`tariffs`, `charges`, `meters`, `readings` из
[plan-backend.md](plan-backend.md), раздел «Схема данных».

## Коротко

- **Основной источник домов - Реформа ЖКХ (АИС ППК «ФРТ»)**, набор «МКД в
  региональной программе капитального ремонта (отчет КР 1.1)». Живой,
  обновлен 01.09.2026, без регистрации, ZIP с CSV. Москва 30 292 дома, СПб
  23 674, Татарстан 17 976 (из них Казань 5 887). Адрес, ФИАС GUID, год,
  этажность, площадь, число помещений, взнос на капремонт - заполнены на 96-100%.
- **Организации - оттуда же**, «Реестр управляющих организаций по РФ»: 49 312
  строк с ИНН, ОГРН, телефоном, почтой, сайтом. **Номера лицензии в нем нет.**
- **ГИС ЖКХ открытых данных по домам и УК не публикует вообще.** Его раздел
  «Открытые данные» - это 123 набора, из которых 121 справочник НСИ. Зато у
  этих наборов есть рабочий публичный REST без авторизации, и справочники
  оттуда ложатся прямо в наши `meters.type`, `tariff_zones`, `tariffs.service`.
- Кадастровый номер, число подъездов, лицевые счета, начисления, показания и
  тарифы на ресурсы **в открытых данных не лежат** - синтезируем или вносим
  руками по шести демо-домам.

## 1. ГИС ЖКХ (dom.gosuslugi.ru)

### Что есть в «Открытых данных»

Каталог лежит по прямому URL и отдается без авторизации:
`https://dom.gosuslugi.ru/opendata/list.xml` (27 КБ, стандарт открытых данных
3.0). В нем 123 набора:

- 121 набор - справочники НСИ: «Вид коммунального ресурса», «Тип прибора
  учета», «Межповерочный интервал», «Объект аварии», «Вид жилищной услуги»,
  «Интервалы тарифных зон суток», «Тип дома», «Способ управления» и так далее;
- 2 набора - «Добавленные в ФИАС дома» и «Добавленные в ФИАС адресные объекты».

**Домов, управляющих организаций, лицензий, лицевых счетов, тарифов и начислений
в открытых данных ГИС ЖКХ нет.** Это главный отрицательный результат по
источнику номер один.

### API у открытых данных все-таки есть

Паспорт каждого набора (`https://dom.gosuslugi.ru/opendata/7710474375-nsi-2/`)
в поле «Гиперссылка (URL) на открытые данные» дает рабочий REST:

    https://dom.gosuslugi.ru/opendataapi/nsi-2/v1?limit=100&offset=0

Без ключа, без ЕСИА, XML на выходе. Потолок `limit` - 100, выше приходит
`errorCode 500, Превышен лимит возвращаемых значений`. Владелец наборов -
Минцифры, дата первой публикации 10.06.2016.

Проверенное содержимое справочников, которые нам прямо нужны:

| Набор | Значения |
|---|---|
| `nsi-2` Вид коммунального ресурса (9) | Холодная вода (ХВ), Горячая вода (ГВ), Электрическая энергия (ЭлЭ), ... |
| `nsi-3` Вид коммунальной услуги (7) | Отопление, ГВС, ХВС, Отведение сточных вод, Электроснабжение, Газоснабжение, Обращение с ТКО |
| `nsi-4` Вид ПУ по количеству тарифов (3) | Однотарифный, Двухтарифный, Трехтарифный |
| `nsi-16` Межповерочный интервал (21) | Значения в годах |
| `nsi-27` Тип прибора учета (4) | Индивидуальный, Коллективный (общедомовой), Общий (квартирный), Комнатный |
| `nsi-50` Вид жилищной услуги (14) | Плата за содержание жилого помещения, Взнос на капитальный ремонт, Пени, Техническое обслуживание, Наем, ... |
| `nsi-57` Объект аварии (3) | Дом, Объект инженерной инфраструктуры, Объект коммунальной инфраструктуры |

Это ровно наши `meters.type`, `meters.tariff_zones`, `tariffs.service` и строки
`charges.lines`. Взять названия оттуда дешево, а на защите это дает фразу «виды
услуг и приборов учета - справочники НСИ ГИС ЖКХ, а не наша фантазия».

### Реестр лицензий

Лежит отдельно от открытых данных: `dom.gosuslugi.ru/#!/licenses`,
«Сводный федеральный реестр лицензий» и «Реестр лицензий субъектов РФ». По
справке системы скачивание идет через UI: «Скачать > Реестр лицензий субъекта
РФ», архив содержит xlsx и отсоединенную электронную подпись оператора ГИС ЖКХ.
Авторизация в справке не упоминается, значит, это открытая часть. Пакетного API
для этого нет.

Внутри фронтенда ГИС ЖКХ есть незадокументированный публичный эндпоинт
`/licenses/api/rest/services/public/house` (найден в бандле `webPackages.js`).
Угадать его контракт не вышло: все пробы отдают 500. Считаем, что его нет.

### API для внешних систем

Существует, но нам не подходит. «Регламент и форматы информационного
взаимодействия внешних информационных систем с ГИС ЖКХ» описывает SOAP-обмен,
через который УК и РСО как **поставщики информации** размещают объекты
жилищного фонда, лицевые счета, приборы учета, показания, платежные документы и
договоры ресурсоснабжения. Нужны регистрация информационной системы в личном
кабинете организации и электронная подпись. Это канал записи для
лицензированной УК, а не публичное чтение справочных данных, и на хакатоне он
недостижим. В спеке интеграция с ГИС ЖКХ уже стоит в Won't, и это обоснованно.

### ПП РФ от 26.01.2026 № 40

Подтверждено: постановление изменило порядок взаимодействия УК с собственниками,
и с 01.09.2026 запись на прием должна быть доступна в том числе через MAX. Под
него Минстрой выпустил приказ от 29.12.2025 № 856/пр (действует с 17.02.2026).
Приказ распространяется на УК, РСО, регоператоров по ТКО и организации по
капремонту: в MAX должны быть постоянно доступны контакты, часы работы, адрес и
часы работы клиентского центра, телефоны диспетчерской и аварийно-диспетчерской
службы, данные о перерывах в предоставлении услуг.

**Требований интегрироваться с ГИС ЖКХ или идентифицировать жителя через ЕСИА в
найденных материалах нет.** Для нас это хорошо: обязанность закрывают функции,
которые у нас и так есть (карточка УК, часы приема, запись на прием,
объявления), без интеграций.

## 2. Реформа ЖКХ (reformagkh.ru)

**Жив и поддерживается.** `www.reformagkh.ru` отдает 301 на
`https://xn--80adsazqn.xn--p1aee.xn--p1ai` (аис.фрт.рф), сайт теперь называется
«АИС ППК ФРТ». Актуальные версии наборов - 01-02.09.2026, период актуализации у
реестра УО «не реже одного раза в квартал», у КР 1.1 «1 раз в месяц».

Скачивание прямое, без регистрации и капчи: `GET /opendata/export/<id>` отдает
ZIP с одним CSV (UTF-8 с BOM, разделитель `;`, имя файла вида
`export-kr1_1-77-20260901.csv`).

### Дома: набор КР 1.1

Идентификаторы экспорта у каждого региона свои (страница `/opendata?gid=`,
где gid: Москва 2280999, СПб 2276347, Татарстан 2353101):

| Регион | export id | ZIP | CSV | Строк |
|---|---|---|---|---|
| Москва | 184 | 2,2 МБ | 11,0 МБ | 30 292 |
| Санкт-Петербург | 250 | 1,8 МБ | - | 23 674 |
| Республика Татарстан | 220 | 1,3 МБ | - | 17 976, Казань 5 887 |

Поля: `subject_rf`, `mun_obr_oktmo`, `mun_obr`, `mkd_code`, `houseguid` (ФИАС
GUID), `address`, `commission_year`, `architectural_monument_category`,
`total_sq`, `total_rooms_amount`, `living_rooms_amount`, `total_rooms_sq`,
`living_rooms_sq`, `total_ppl`, `number_floors_max`, `money_collecting_way`,
блок финансирования капремонта, `owners_payment`, `energy_efficiency`,
`inclusion_date_to_program`, `last_update`, `house_id`.

Заполненность по нашим трем регионам: `houseguid` 99-100%, `commission_year`
100%, `total_sq` 100%, `number_floors_max` 99-100%, `living_rooms_amount`
97-100%, `owners_payment` 96-100%. `energy_efficiency` в Москве пуст полностью,
в СПб и РТ заполнен на 99-100%.

Формат адреса зависит от региона, поэтому под каждый нужен свой парсер:

- Москва: `60-летия Октября просп. 10/1` - без города, тип улицы в конце;
- СПб: `г. Зеленогорск, Авиационная ул., д. 10 литера А` - с литерой;
- Казань: `г. Казань, Авиастроительный р-н` в `mun_obr`, адрес `ул. 2-я
  Ленинградская, д. 4`.

**Чего в наборе нет:** кадастрового номера и числа подъездов.

### Организации: реестр УО

`export/1`, 22,2 МБ CSV, 49 312 строк. Поля: `id`, `subject_rf`, `name_full`,
`name_short`, `name_employee`, `inn`, `orn` (ОГРН), `legal_address`,
`actual_address`, `phone`, `email`, `site`, `count_mkd`, `area_total`, `w_summ`
(рейтинг портала). Строк с упоминанием Москвы 2 655, Санкт-Петербурга 3 481,
Татарстана 1 243.

**Чего нет:** номера лицензии и списка домов организации. Связку дом - УК
набор не дает ни в одну сторону.

### Карточка дома закрывает оба пробела

`https://www.reformagkh.ru/myhouse/profile/view/<house_id>` отдает HTML (221 КБ)
с блоком «Домом управляет» (для проверенного дома - ГБУ «Жилищник района
Академический»), полями «Количество подъездов, ед.», «Количество этажей, ед.»,
«Год ввода дома в эксплуатацию» и площадями. Кадастрового номера на ней нет.
`house_id` берется из поля `house_id` набора КР 1.1 (заполнено на 72-91%).

Для шести демо-домов это шесть ручных открытий страницы. Автоматизировать
незачем.

### Аварийный жилфонд - единственный набор с кадастром

`export/427`, «Аварийный жилищный фонд по Российской Федерации», поля включают
`cadastral_number`, `cadastral_registration_date`, `entrance_count`,
`built_year`, `project_type`, `house_type`, `area_land`. Все это ровно то, чего
не хватает в КР 1.1, но набор покрывает только аварийные дома, а селить туда
демо неуместно. Использовать можно разве что как образец формата кадастрового
номера.

### Лицензия и условия

Явного текста лицензии или условий использования на сайте не нашлось: в паспорте
набора поля с лицензией нет, на `/about` условий нет, контакт -
`support@reformagkh.ru`. Данные раскрываются в силу ПП РФ № 731 и приказов
Минстроя, то есть публичны по назначению. **Практический вывод:** выдержку в
несколько сотен строк в публичный репозиторий класть можно, полные выгрузки
(34 МБ CSV) - незачем, они скачиваются скриптом.

## 3. Прочие источники

### ФИАС / ГАР

Работает и открыт. `https://fias.nalog.ru/WebServices/Public/GetLastDownloadFileInfo`
отдает JSON с версией и ссылками. На 16.09.2026 актуальна версия 20260915,
полный ГАР - `https://fias-file.nalog.ru/downloads/2026.09.15/gar_xml.zip`,
**57 562 261 156 байт (53,6 ГиБ)**. Есть дельты (`GarXMLDeltaURL`) и старый
КЛАДР (`Kladr47ZUrl`).

Для двухнедельного хакатона это не источник: распаковка и разбор ГАР съедят день
и не дадут ничего сверх того, что есть в КР 1.1, где адрес уже нормализован и
рядом лежит `houseguid`.

### Координаты

Нужны для гео-онбординга. `houseguid` в КР 1.1 есть, но координат в ГАР по
зданиям нет, так что геокодировать все равно придется.

- **Nominatim (OSM)** - проверен, работает, отдает `lat`/`lon` и явную лицензию
  `Data (c) OpenStreetMap contributors, ODbL 1.0`. Лимит - 1 запрос в секунду,
  нужен осмысленный `User-Agent`. Для 300-400 адресов это 5-7 минут.
  ODbL требует атрибуции, а для производной базы - share-alike, поэтому
  атрибуцию в README пишем.
- **DaData Suggestions** - бесплатно до 10 000 запросов в сутки, не более 30 rps
  с одного IP, до 20 результатов на запрос; возвращает `geo_lat`/`geo_lon`,
  ФИАС и КЛАДР коды. Нужен ключ и регистрация. Условия оферты насчет хранения и
  публикации результатов **проверить не удалось** - в публичный репозиторий
  координаты от DaData класть без чтения оферты не стоит.

Рекомендация: Nominatim, он без ключа и с понятной лицензией.

### ЕГРН, Росреестр, кадастр

- Выписки из ЕГРН **платные**, это не открытые данные: 290 руб за электронную
  для физлица, 1 640 руб для организаций с 26.04.2026.
- Открытые данные Росреестра - это реестр лицензий на геодезическую и
  картографическую деятельность, реестр СРО кадастровых инженеров, результаты
  проверок. По объектам недвижимости ничего.
- Публичная кадастровая карта (`pkk.rosreestr.ru`) и НСПД (`nspd.gov.ru`)
  используют сертификаты российского удостоверяющего центра: из нашей среды
  TLS-рукопожатие падает («self signed certificate in certificate chain»).
  Из РФ с установленным корневым сертификатом Минцифры они, вероятно, работают,
  но полагаться на это в демо нельзя.

Вывод: **кадастровый номер шести демо-домов вносим руками** (или оставляем
пустым - карточка дома это переживет).

### Порталы городов

- **data.mos.ru**: из нашей среды не открывается, TLS-рукопожатие обрывается
  (`SSL_ERROR_SYSCALL`), через веб-прокси отдается только оболочка SPA. По
  поисковой выдаче на портале есть наборы «Перечень управляющих компаний и
  товариществ собственников жилья, осуществляющих свою деятельность на
  территории города Москвы» и «Адресный реестр объектов недвижимости города
  Москвы» (`/opendata/60562`). API - `apidata.mos.ru`, нужен `api_key` по
  регистрации. **Содержимое наборов не проверено**, брать их основным
  источником нельзя.
- **data.gov.spb.ru**: мертв. Прямой запрос - таймаут, в выдаче заголовок «Сайт
  переехал!», ГИС «Открытые данные» слита с системой классификаторов
  (`classif.gov.spb.ru`). Тематические наборы частично живут на портале «Наш
  Санкт-Петербург» (`gorod.gov.spb.ru`, отвечает 200).
- **open.tatarstan.ru**: отвечает 302, дальше из нашей среды таймаут. Каталог
  наборов по ЖКХ не проверен.

Все три портала для нашей задачи не нужны: КР 1.1 покрывает и Москву, и СПб, и
Казань одним форматом, а разные форматы трех порталов - это три парсера вместо
одного.

## 4. Регион-специфика: показания и начисления

Публичного API, через который можно передать показания или получить
начисления, нет ни в одном из трех городов.

### Москва

Передача показаний идет через ЕМП / mos.ru, окно приема - с 15 по 26 число
месяца. Официального публичного API нет. Сообщества разобрали протокол
мобильного приложения `emp.mos.ru`: `github.com/alryaz/hass-moscow-pgu`
(интеграция для Home Assistant) и `github.com/dontsovcmc/emp_mos_api`
(библиотека). Это неофициальная реверс-инженерия личного кабинета. Для продукта
на хакатоне она неприменима: требует учетных данных жителя и нарушает условия
сервиса.

Отдельно: у Москвы уже есть прямой аналог нашего продукта - «Электронный дом»
(`ed.mos.ru`) и `dom.mos.ru`. Это стоит знать для позиционирования, а не как
источник данных.

### Санкт-Петербург

ГУП ВЦКП «Жилищное хозяйство» - `kvartplata.info`, личный кабинет
`lk.kvartplata.info`, показания до 25 числа. Публичного API нет, документации
для интеграции третьих лиц не найдено.

Петроэлектросбыт / ПСК - `pesc.ru`, есть мобильное приложение. Протокол разобран
сообществом: `github.com/dentra/ha-pesc`. Официального API нет.

### Казань

«Услуги РТ» (`uslugi.tatarstan.ru`) и приложение «Услуги РТ» дают передачу
показаний и оплату ЖКУ по лицевому счету; Татэнергосбыт описывает передачу
показаний через этот портал. Документации для разработчиков, API или описания
интеграции найти не удалось.

**Вывод для продукта.** Это подтверждает границу, которая в спеке уже проведена:
начисления формирует биллинг УК, а мы их не считаем. Точка интеграции в проде -
выгрузка из биллинга в таблицу `charges`, и на слайде масштабирования это
честнее, чем обещание подключиться к чему-то, чего не существует.

## 5. Что придется синтезировать

Из открытых источников в принципе не получить:

- **лицевые счета** (`flats.account_no`) - персональные данные, нигде не
  публикуются;
- **начисления и квитанции** (`charges`) - биллинг УК;
- **показания счетчиков** (`readings`) и сами счетчики (`meters`, серийные
  номера, даты поверки);
- **квартиры** (`flats`) - номера, площади, привязка к подъездам;
- **тарифы на ресурсы** (`tariffs`, кроме взноса на капремонт) - публикуются на
  сайтах РСО и в открытой части ГИС ЖКХ как страницы, машиночитаемой выгрузки
  нет; для шести домов проще внести руками 4-6 значений на город;
- **кадастровый номер** и **число подъездов** для неаварийных домов.

Единственный настоящий тариф, который приезжает готовым, - взнос на капитальный
ремонт из `owners_payment`:

| Город | Медиана, руб/кв.м | Диапазон |
|---|---|---|
| Москва | 32,63 | 29,66 - 32,63 |
| Санкт-Петербург | 11,50 | 3,00 - 12,00 |
| Казань | 10,16 | 5,85 - 10,16 |

## Рекомендация для сида

Один скрипт `scripts/fetch_source_data.py`: качает три ZIP по КР 1.1 и реестр УО,
фильтрует, пишет компактные CSV в `backend/seed/data/`. Полные выгрузки в
репозиторий не коммитим, кеш загрузки - в `.gitignore`. Бюджет - полдня.

### Шаг 1. Справочник адресов для пикера

Из КР 1.1 берем по одной большой улице на город. Проверенные кандидаты с числом
домов:

- Москва: `Ленинский просп.` - 76 домов (либо `Первомайская ул.` - 65);
- Санкт-Петербург: `Гражданский пр.` - 178 (либо `Московский пр.` - 149);
- Казань: `пр-кт. Победы` - 110 (либо `ул. Восстания` - 100).

Всего около 360 строк - пикер выглядит справочником, а не заглушкой, как и
требует спека. Если многовато, режем до 50-60 домов на улицу.

### Шаг 2. `houses`

Прямое отображение полей КР 1.1:

| Колонка `houses` | Источник |
|---|---|
| регион, город | `subject_rf`, `mun_obr` (для Москвы город подставляем) |
| улица, дом | разбор `address`, парсер на регион |
| год | `commission_year` |
| этажность | `number_floors_max` |
| площадь | `total_sq` |
| кадастр | **руками для 6 демо-домов**, у остальных `null` |
| число подъездов | **руками с карточки** `/myhouse/profile/view/<house_id>` для 6 домов; остальным оценка `ceil(living_rooms_amount / (number_floors_max * 4))` с пометкой в коде |
| lat, lon | Nominatim по адресу, атрибуция ODbL в README |
| org_id | для 6 демо-домов - по блоку «Домом управляет» карточки; для остальных `null`, это и есть штатное «УК не подключена» |

Полезный побочный эффект: `living_rooms_amount` и `living_rooms_sq` дают
реальную среднюю площадь квартиры по дому - синтетические `flats` получатся
правдоподобными без выдумывания.

### Шаг 3. `organizations`

Из реестра УО фильтруем по `subject_rf` и берем 8-12 организаций: 3-4 «подключенных»
(у них будут дома и сотрудники) и 5-8 «неподключенных» для сценария плашки и
`demand_signals`.

- `name` - `name_short`, `inn` - `inn`, телефон и почта в карточку дома -
  `phone`, `email`, `site`.
- `license_no` - **вручную** из реестра лицензий ГИС ЖКХ
  (`dom.gosuslugi.ru/#!/licenses`) для тех 3-4 организаций, что попадут в демо.
  Остальным оставляем пустым. Придумывать номер лицензии нельзя: по нему в
  продукте ищется организация при регистрации, и фальшивый номер в демо -
  ровно то, что жюри проверит.

### Шаг 4. `tariffs`

- `service` - из справочников ГИС ЖКХ `nsi-3` (коммунальные) и `nsi-50`
  (жилищные), названия один в один.
- Взнос на капремонт - реальный, из `owners_payment` того же дома.
- ХВС, ГВС, электроэнергия, содержание - руками по городу с сайтов РСО или из
  открытой части ГИС ЖКХ, по две строки на услугу: `valid_from` до 1 июля и
  после. Одно повышение в истории спека требует прямо - без него разбору
  квитанции нечего показывать.

### Шаг 5. `meters`, `readings`, `charges`, `flats` - синтез

- `flats`: по `living_rooms_amount` и `living_rooms_sq` дома, раскладка по
  подъездам и этажам. `account_no` - детерминированный генератор от id дома и
  номера квартиры, чтобы сид был воспроизводим.
- `meters.type` - из `nsi-2` / `nsi-3`, `tariff_zones` - из `nsi-4`
  (однотарифный / двухтарифный / трехтарифный), `next_verification_date` - от
  даты установки плюс межповерочный интервал из `nsi-16`. Один счетчик в
  демо-квартире делаем с поверкой через 3 недели - это ровно сценарий
  предупреждения бота.
- `readings`: 6 месяцев, случайное блуждание вокруг реалистичного расхода
  (холодная вода 3-5 куб.м на человека в месяц), с одним выбросом в последнем
  месяце для сценария «возможная скрытая протечка» и одним показанием ниже
  предыдущего для флага в кабинете УК.
- `charges.lines`: считаются из `readings` и `tariffs` тем же кодом, который
  потом делает разбор квитанции. Иначе разбор будет показывать дельты, которых
  в данных нет.

### Что показать жюри

Формулировка для презентации и README, которая держится на проверяемом:

> Дома, их характеристики и управляющие организации - реальные, из открытых
> данных АИС ППК «ФРТ» (Реформа ЖКХ) от 01.09.2026. Виды услуг, типы приборов
> учета и межповерочные интервалы - справочники НСИ ГИС ЖКХ. Взнос на
> капитальный ремонт - настоящий по каждому дому. Лицевые счета, начисления и
> показания - модельные: они персональные и нигде не публикуются.

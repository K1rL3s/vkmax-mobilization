## B. Платформа и реализация

- [x] **[!]** Решение сделано как чат-бот или как чат-бот с подключённым мини-приложением. Мини-приложение не работает в отрыве от бота (constr 5)
- [ ] **[!]** Функциональность доступна и в мобильной, и в веб-версии MAX (constr 3, web)
- [ ] **[!]** Сдаётся бот с токеном, который выдали организаторы (task 4, info, web)
- [x] **[!]** Мини-приложение привязано к выданному боту: HTTPS-ссылка отправлена организаторам через форму, привязку делают они (faq 2)
- [x] **[!]** Название, ник, логотип и административные настройки выданного бота не меняются; настройку, недоступную через API, просят у организаторов (faq 16, 19)
- [x] **[!]** Код написан командой, no-code и low-code конструкторы не служат основой решения (faq 9)
- [x] **[!]** Мини-приложение работает по HTTPS (info, web)
- [x] Бот работает через вебхуки, а не через long polling (web)
- [x] **[!]** Бот и хостинг онлайн весь период проверки, с 30 сентября по 14 октября, чтобы эксперты в любой момент прошли сценарий сами; лимиты внешних сервисов не кончаются раньше (web, faq 11)
- [x] Логика разделена разумно: в чате короткие диалоги, выбор из нескольких вариантов, статусы и уведомления; в мини-приложении сложные формы, списки, сравнение и возврат к данным (info)
- [x] Учтены ограничения MAX: ник бота нельзя изменить, бот не создаёт чаты, бот помнит около 1000 чатов, рекламные рассылки запрещены (constr 11, web)
- [x] Реализация сверена с актуальной документацией MAX (dev.max.ru/docs) (info)
- [x] Собственный API не обязателен и сам по себе баллов не даёт (constr 6)

- [x] **[!]** Нет закрытых библиотек, частных API и чужого кода без свободной лицензии (constr 7)
- [x] Сторонние API только публичные и документированные, используются по условиям сервиса; их лимиты учтены в плане масштабирования (faq 6)
- [x] **[!]** В репозитории нет рабочих токенов, паролей, ключей и других секретов (constr 8, crit)
- [x] **[!]** Соблюдаются законодательство РФ, правила платформы MAX и правила хакатона (constr 9)
- [x] **[!]** Если используются тестовые, смоделированные или заранее подготовленные данные вместо реальной интеграции, это явно указано и в презентации, и в README (constr 10, rec 5, info, faq 13)
- [x] Модельные данные помечены и в README, и в самом боте (web)
- [x] Интеграции не имитируются: указано, какие из них модельные и что нужно для настоящей реализации; mock не выдаётся за работающую интеграцию (info, faq 15)
- [x] Используются обезличенные, тестовые или синтетические данные (rec 5, web)
- [x] Если собираются персональные данные, пользователь даёт согласие на их обработку по 152-ФЗ (web)
- [x] Учтены ПП РФ № 416 (п. 34-35, порядок и сроки ответа на обращения) и порядок работы с обращениями граждан (info, web)
- [x] Для данных указаны источник, территория, период и дата актуальности (rec 5, info)
- [x] Разделены официальные факты, расчёты продукта, рекомендации и допущения (info)
- [x] Если используется LLM: ответы привязаны к источникам и показывают основание; предусмотрен случай, когда надёжного ответа нет; догадка модели не выдаётся за факт (info)
- [x] Честно указано, где при разработке использовался ИИ (web)
- [ ] **[!]** ИИ только вспомогательный инструмент: решение разработано и понимается командой, результат генеративного ИИ не сдаётся как готовое решение (faq 8)
- [x] Доступ к данным соответствует логике решения, очевидных критичных рисков безопасности нет (crit)

### Только если есть собственный API (sub, faq 12)

Собственный API - HTTP(S)-методы, которые входят в продукт. Бэкенд мини-приложения под это подпадает: организаторы подтвердили, что для него нужен DATA-API.yaml.


- [ ] HTTPS-адрес API, доступный весь период проверки
- [x] `openapi.yaml` или `openapi.json` (OpenAPI 3.0/3.1)
- [x] Тестовые учётные записи для нужных ролей
- [x] Тестовые данные (JSON, CSV и т. п.)
- [ ] `DATA-API.yaml`: версия схемы, название или ID команды, базовый URL, список обязательных проверок, метод и путь, параметры, роль, ожидаемые статус-коды, формат ответа

## E. Онлайн-этап: продуктовая оценка (40%)

### E1. Потенциал масштабирования - 35%
- [ ] Названы конкретные регионы, организации и контексты за пределами исходного кейса

- [ ] Определены условия адаптации: данные, интеграции, ресурсы, изменения продукта
- [ ] Отделено ядро продукта (проблема, логика сценария, архитектура, модель данных, механика, UI) от переменной части (региональные данные, нормативы, справочники, внешние системы, роли, правила) (rec 6, info)
- [ ] Учтены ограничения и риски масштабирования
- [ ] Предложен реалистичный порядок тиражирования, а не «запустим по всей России»
- [ ] Желательно: оценка TAM/SAM/SOM (web)

### E2. Пользовательская ценность - 25%
- [ ] Определены ЦА и приоритетный сегмент, конкретнее, чем просто «жители» (rec 1, task 1)
- [ ] Описана конкретная и актуальная потребность, например по формуле «[пользователь] в ситуации [контекст] хочет [результат], но [барьер], из-за чего [последствие]» (info)
- [ ] Сформулирован полезный результат для пользователя
- [ ] Показано преимущество перед текущим способом: As Is → To Be, сравнение с конкурентами (info, web)
- [ ] Востребованность подтверждена данными, наблюдениями, интервью или аргументированными допущениями; факты отделены от гипотез (rec 2)

### E3. UX/UI - 20%
- [ ] Основной путь соответствует приоритетному сценарию (rec 3)
- [ ] Последовательность действий понятна без пояснений
- [ ] Ключевые действия, навигацию и элементы легко найти и однозначно понять
- [ ] Интерфейс сообщает о загрузке, результате и ошибке
- [ ] Нет лишних шагов, тупиков и противоречивых переходов

### E4. Обоснованность и целостность - 15%
- [ ] Решение соответствует задаче и выбранной проблеме
- [ ] Прослеживается логика «проблема → механика → результат»; технология выбрана под задачу, а не наоборот (rec 4)
- [ ] Ключевые продуктовые решения и допущения аргументированы
- [ ] Функции согласованы и образуют один продукт
- [ ] Решение реалистично с учётом условий и ограничений; границы MVP определены, включая Won't Have (info)
- [ ] Определён ожидаемый эффект и хотя бы одна метрика для проверки: время, число ручных действий, ошибки, доля завершивших сценарий, повторные обращения (task 6, info)

### E5. Качество презентации - 5%
- [ ] Структура быстро объясняет проблему, решение и результат
- [ ] Ключевые мысли сформулированы ясно

- [ ] Схемы, изображения и демо читаемы
- [ ] Слайды не перегружены второстепенным и повторами

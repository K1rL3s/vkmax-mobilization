# Общий FAQ

Частые вопросы организаторов. Если ответа на вопрос в списке нет, пишите на support@hackathon-max.vk.company

## 1. Обязательно ли делать мини-приложение?

Нет. Решение может быть реализовано как чат-бот или как чат-бот с подключённым мини-приложением.

## 2. Как подключить мини-приложение к выданному боту?

Сначала разместите мини-приложение по публичной HTTPS-ссылке, затем отправьте её через форму https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/. Привязку к боту выполняют организаторы. Регистрироваться в «MAX для партнёров» не нужно.

## 3. Можно ли тестировать мини-приложение локально?

Локально можно проверять веб-интерфейс и логику. Для полноценного тестирования внутри MAX приложение необходимо разместить по HTTPS и подключить к выданному боту (см. вопрос 2).

## 4. Где найти имя бота, если прислали только токен?

Выполните запрос `GET /me` с выданным токеном. В ответе будет username бота, по которому его можно найти в MAX (и другая полезная информация).

```sh
curl -X GET "https://platform-api2.max.ru/me" \
  -H "Authorization: ВАШ_ТОКЕН"
```

## 5. Обязательно ли использовать JavaScript и React?

Нет. Это рекомендация. Можно использовать другие языки программирования и API при соблюдении технических требований кейса.

## 6. Можно ли использовать сторонние API?

Да, если это публичные документированные API и их использование соответствует условиям сервиса. Закрытые и частные API использовать нельзя. Также учитывайте ограничения API при дальнейшем масштабировании решения.

## 7. Обязательно ли использовать Docker?

Да. Решение должно быть подготовлено для воспроизводимого запуска через Docker. Если используются внешние сервисы, которые невозможно запустить внутри Docker, их необходимо описать в README.

## 8. Можно ли использовать AI-инструменты и AI-агентов?

Да, как вспомогательный инструмент - например, для подсказок при написании кода или подготовки черновиков документации. Итоговое решение должно быть разработано и пониматься самой командой; сдавать результат генеративного ИИ как готовое решение задания нельзя.

## 9. Можно ли использовать no-code/low-code конструкторы?

Формат хакатона предполагает самостоятельную разработку кода участниками. Поэтому no-code/low-code конструкторы не следует использовать как основу конкурсного решения.

## 10. Когда и куда сдавать решение?

До 30 сентября, 12:00 по московскому времени в личном кабинете. После дедлайна переданная версия решения фиксируется и не изменяется.

## 11. Нужно ли оставлять бота работающим после сдачи?

Да. Решение должно оставаться доступным на протяжении периода проверки, чтобы эксперты в любое время могли самостоятельно пройти основной пользовательский сценарий.

## 12. Что считается собственным API и когда нужен DATA-API.yaml?

Если решение предоставляет собственные HTTP(S)-методы, которые являются частью продукта, это считается собственным API. Для него нужны HTTPS-адрес, OpenAPI 3.0/3.1, тестовые данные/доступы и DATA-API.yaml. Если своего API нет, DATA-API.yaml не нужен.

## 13. Что делать, если нет доступа к реальной внешней системе?

Можно использовать тестовые, синтетические или заранее подготовленные данные. В презентации и README нужно явно указать, какие интеграции являются модельными и что потребуется для их реализации после MVP.

## 14. Можно ли придумать свою проблему внутри выбранного трека?

Да. Необязательно ограничиваться приведёнными в кейсе примерами. Главное, чтобы задача соответствовала тематике выбранного трека, её актуальность была обоснована, а решение соответствовало требованиям кейса.

## 15. Можно ли использовать mock-интеграцию вместо настоящей?

Да, если реальная интеграция недоступна. Но нельзя выдавать её за работающую реальную интеграцию - в материалах нужно явно обозначить, что именно смоделировано.

## 16. Можно ли менять название, ник или логотип выданного бота?

На онлайн-этапе - нет. Команда работает с выданным ботом и его текущими настройками. Возможность изменить название, ник и логотип будет предоставлена финалистам.

## 17. Нужен ли собственный домен для мини-приложения?

Нет. Главное, чтобы приложение было доступно по публичной HTTPS-ссылке. Это может быть адрес, предоставленный выбранным вами хостингом.

## 18. Можно ли использовать приватный репозиторий?

Да. Самый безопасный вариант - передать архив исходного кода с контрольной суммой, чтобы эксперты гарантированно могли получить доступ к зафиксированной версии решения. При этом рекомендуем также указать ссылку на репозиторий на случай форс-мажора или необходимости дополнительной проверки.

## 19. Можно ли самостоятельно изменить административные настройки выданного бота?

Нет. Участникам предоставляется технический доступ через токен, но не административный доступ к боту. Если для сценария требуется настройка, недоступная через API, необходимо обратиться к организаторам.
